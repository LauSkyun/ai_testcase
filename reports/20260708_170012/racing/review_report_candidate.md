# 需求文档分析报告

## 一、总体评价
文档主流程可理解，但仍存在“干扰指数”与“Luck(随机扰动)”的映射关系缺失、奖池状态计算公式存在分母为0的致命缺陷及阈值占位符、开奖时间T的动态计算与固定5S动画表现存在冲突等高风险问题，建议补充对齐后再推进开发与测试。

- **文档质量评分：** C
- **评分原因：** 主流程可理解，但仍存在高风险缺口或关键边界缺失，需要补充后再完整开工。

## 优先处理事项
- **[高] “干扰指数”与“Luck(随机扰动)”的映射关系缺失**
  - 责任建议：数值策划
  - 处理原因：若映射关系不清，干预逻辑将无法落地，或导致干预方向与预期相反，严重破坏游戏平衡和收益。
- **[高] 奖池状态计算公式存在分母为0的致命缺陷及阈值占位符**
  - 责任建议：数值策划
  - 处理原因：1、除零导致服务崩溃或干预逻辑失效；2、阈值缺失导致无法数值验证；3、MAX可能超限额下注，引发UI与服务器扣款不一致；4、UI展示逻辑混乱，用户无法理解下注时的速度预期。
- **[高] 开奖时间T的动态计算与固定5S动画表现存在冲突**
  - 责任建议：系统策划
  - 处理原因：1、若使用不同赔率口径，会导致客户端展示与真实赔付不符，引发重大资损或客诉；2、若T与5S不一致，动画播放完毕但结算未出，或结算已出但动画未播完，破坏用户体验并可能引发‘假动画’质疑。

## 二、逐维度问题清单
### 【清晰度与完整性】
- **[严重程度：高] 奖池状态计算公式存在分母为0的致命缺陷及阈值占位符**
  - 现状描述：1. 奖池状态计算公式为((今日+昨日收入)-(今日+昨日支出))/(今日+昨日收入)，若刚上线或某时段无下注，分母为0，导致除零。
2. 奖池状态阈值全为[001]%、[002]%占位符，未给出具体数值，无法实现干预逻辑。
3. 下注档位包含MAX（消耗所有余额），同时规定单选项单轮次最多下注100万，未说明当余额>100万时，点击MAX的实际扣款逻辑（是截断为100万还是提示）。
4. 下注阶段只展示1段地形，另外2段隐藏，开奖时随机出现，但统计板块展示‘各地形速度’，且下注界面展示‘各车型在已知地型的车速’，未明确客户端在开奖前如何计算并展示预期速度。
  - 证据来源：musee游戏Racing.docx / 3.4开奖逻辑 段落39；3.3下注部分 段落32、26-27、31
  - 风险分析：1、除零导致服务崩溃或干预逻辑失效；2、阈值缺失导致无法数值验证；3、MAX可能超限额下注，引发UI与服务器扣款不一致；4、UI展示逻辑混乱，用户无法理解下注时的速度预期。
  - 修改建议：1. 增加分母为0时的默认状态定义（如默认归为‘待补充’）。
2. 补充具体的阈值数值（如≤10%待补充，10%-30%正常，≥30%充裕）。
3. 明确MAX按钮的截断逻辑：当余额>100万时，MAX实际下注金额应为100万，并在UI给出提示。
4. 明确客户端在开奖前仅展示当前已知1段地形的速度，或与UI设计对齐的综合预期速度。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：高] 开奖时间T的动态计算与固定5S动画表现存在冲突**
  - 现状描述：1、1. 赔率公式冲突：需求文档定义实时赔率=合计下注/本选项下注*[001]%，并明确‘实际赔率时也按这个赔率去赔付’；2、数值文档定义odds=max(T*(1-x)/W,1.02)和Odds_X = ((T × (1 - r)) / W_X) × γ，且提到‘分实际赔率和假赔率’。两套公式不一致，且T、x、W、r、γ等变量无业务定义和取值范围。；3、2. 开奖时间与动画冲突：需求文档规定开奖阶段固定5S（段落7），数值文档公式T = L / [V * K * Luck] 为动态计算值（图片3），未说明当T≠5S时，客户端动画如何与真实结算时间对齐。
  - 证据来源：musee游戏Racing.docx / 3.3下注部分 段落28、3.1首页顶栏板块 段落7、3.4开奖逻辑 段落36；Racing数值文档.docx / 段落3、图片1、图片3
  - 风险分析：1、若使用不同赔率口径，会导致客户端展示与真实赔付不符，引发重大资损或客诉；2、若T与5S不一致，动画播放完毕但结算未出，或结算已出但动画未播完，破坏用户体验并可能引发‘假动画’质疑。
  - 修改建议：1. 统一赔率计算模型，明确需求文档的实时赔率是用于展示还是结算，若为展示则说明假赔率逻辑，并明确数值文档公式为结算赔率。
2. 定义T与5S的映射规则，建议增加动画播放速率动态调整或结算等待/跳过机制，确保客户端表现与服务端T值严格同步。
3. 补充数值文档公式中T、W、γ、r等变量的业务定义、取值范围及配置表示例。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞开发

### 【逻辑一致性与数值平衡】
- **[严重程度：高] “干扰指数”与“Luck(随机扰动)”的映射关系缺失**
  - 现状描述：1、需求文档提到通过调整‘干扰指数’（如1.01-1.1）来干预开奖；2、数值文档公式T = L / [V * K * Luck]中包含‘Luck(随机扰动)’。未说明干扰指数是否等同于Luck，以及其作用方向（如1.01是让T变大还是变小）。
  - 证据来源：musee游戏Racing.docx / 3.4开奖逻辑 段落40、43；Racing数值文档.docx / 图片3
  - 风险分析：若映射关系不清，干预逻辑将无法落地，或导致干预方向与预期相反，严重破坏游戏平衡和收益。
  - 修改建议：1、明确干扰指数即为Luck变量，并说明当干扰指数>1时，T变小（速度变快），从而增加获胜概率；2、提供具体的配置表示例。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：中] 新用户/流失用户干预与奖池干预的优先级与风控冲突**
  - 现状描述：文档规定‘优先看新用户/流失用户逻辑，其次进入奖池状态判断’。但当奖池‘待补充’（需开投注人数最少的）与‘新用户下注人数最多’冲突时，优先满足新用户会导致奖池进一步亏损，缺乏风控兜底。
  - 证据来源：musee游戏Racing.docx / 3.5新用户和预流失用户体验优化 段落51、57；3.4开奖逻辑 段落49
  - 风险分析：缺乏风控兜底，可能导致恶意用户利用新用户/流失身份持续薅羊毛，造成奖池严重亏损。
  - 修改建议：增加风控兜底逻辑：当满足新用户干预条件，但会导致奖池状态恶化至危险阈值（如负数或低于某下限）时，强制降级为奖池干预逻辑。
  - 关注角色：数值策划
  - 置信度：中
  - 阻塞级别：阻塞测试用例设计

### 【可测试性与验收标准】
- **[严重程度：中] 假数据注入对实时赔率计算的污染风险**
  - 现状描述：下注人数/金额含假数据（真实*系数）。需求文档规定实时赔率=合计下注/本选项下注。未明确服务端计算赔率时，使用的是真实下注还是包含假数据的下注。
  - 证据来源：musee游戏Racing.docx / 3.3下注部分 段落22-23、28
  - 风险分析：若使用假数据计算赔率，会导致赔率严重失真，真实用户下注后实际赔付与展示不符。
  - 修改建议：1、明确验收标准：服务端计算实时赔率及最终结算时，必须使用真实下注数据；2、假数据仅用于客户端UI展示。

## 三、核心测试点建议
### 功能验证
- 验证下注、开奖、结算主流程，确保扣款与发奖金额准确。
- 验证实时赔率计算逻辑，对比客户端展示与服务端实际结算赔率。
- 验证奖池状态计算及干预逻辑（充裕、正常、待补充）是否按预期触发。
- 验证新用户/流失用户干预逻辑的触发条件及开奖结果。
- 验证榜单、统计、下注记录的数据准确性及排序逻辑。
- 验证引导局表现，确认不扣真实资产、不注入奖池、不统计。
### 异常操作
- 验证奖池收入为0时，状态计算是否报错或降级。
- 验证极端下注比例下，最低赔率兜底逻辑（如1.02）是否生效。
- 验证单选项下注达到100万上限后，继续下注的拦截提示。
- 验证断线重连后，下注状态、开奖动画及结算结果的恢复。
### 兼容性
- 验证全屏与半屏模式下的UI适配及按钮交互。
- 验证弱网环境下，下注请求的幂等性及开奖结果的同步。
### 安全专项
- 验证假人数/假金额数据是否严格隔离，未参与服务端赔率计算。
- 验证客户端篡改下注金额或选项时，服务端的校验与拦截。
- 验证自动化/白名单干预逻辑的权限控制及日志记录。
### 回归影响
- 验证配置热更（如干扰指数、地形概率）后，历史局及进行中的局是否受影响。
- 验证新版本上线后，旧版本客户端的兼容性及降级策略。
### 性能与稳定性
- 验证下注人数/金额高频更新（[001]S）对服务器及客户端性能的影响。
- 验证开奖动画播放时长与动态T值的同步机制，确保无卡顿或穿模。
### 用户体验
- 验证蒙层引导流程的顺畅度及固定数值展示的合理性。
- 验证中奖/未中奖结果弹窗的信息展示及TOP3用户排名的准确性。
- 验证音效开关的持久化及不同场景下的音效表现。
