# 需求文档分析报告

## 一、总体评价
文档整体描述了疯狂777的基础玩法、UI框架和数值结构，但核心结算链路（特别是RESPIN累加公式、盘面符号优先级、推展机制）存在多处自相矛盾和定义缺失，直接阻塞核心逻辑开发与测试用例设计。

- **文档质量评分：** C
- **评分原因：** 主流程可理解，但核心结算公式（RESPIN加法/乘法、固定次数/独立随机）和盘面生成规则（符号优先级、风控0倍逻辑）存在多处高风险冲突，需补充明确后方可开工。

## 优先处理事项
- **[高] RESPIN结算公式（加法/乘法）与次数控制逻辑存在三处矛盾**
  - 责任建议：数值策划
  - 处理原因：核心结算链路无法实现，RTP无法计算，直接阻塞开发与测试。
- **[高] 基础盘面“any/any bar/any 7”互斥优先级未定义**
  - 责任建议：系统策划
  - 处理原因：服务端在生成盘面时，若按权重随机出混合符号，将无法确定最终赔付类型，导致结算错误或死循环。
- **[高] 推展（Tease）机制的触发阈值定义与盘面表现冲突**
  - 责任建议：数值策划
  - 处理原因：推展机制无法落地，表演系统与结算系统脱节。

  - 现状描述：文档定义了any、any bar、any 7的符号组合，并强调“盘面不会同时满足多个条件，有且只能有一种结果”，但当盘面出现混合符号（如2个bar+1个7）时，未说明匹配优先级。
  - 证据来源：疯狂777需求文档修改后.docx / 段落10-13；crazy777数值文档修改后.docx / 段落10-14
  - 风险分析：服务端在生成盘面时，若按权重随机出混合符号，将无法确定最终赔付类型，导致结算错误或死循环。
  - 修改建议：在数值文档中补充基础盘面符号的匹配优先级规则（例如：777 > 77 > 7 > any 7 > bar2 > bar > any bar > any > 空），明确混合符号的降级或互斥逻辑。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：中] 中奖金额缩位展示的“向下取整”边界定义不严谨**
  - 现状描述：需求文档举例15555显示15.55K，说明是向下取整保留两位小数。但未明确如果是15559，是显示15.55K还是15.56K，以及0或极小值的展示规则。
  - 证据来源：疯狂777需求文档修改后.docx / 段落30
  - 风险分析：客户端UI展示与预期不符，可能引发用户客诉。
  - 修改建议：明确公式为 `floor(金额 / 1000 * 100) / 100`，并补充0值及小于1000数值的展示规则（如直接显示整数）。
  - 关注角色：前端程序
  - 置信度：中
  - 阻塞级别：阻塞测试用例设计

### 【逻辑一致性与数值平衡】
- **[严重程度：高] RESPIN结算公式（加法/乘法）与次数控制逻辑存在三处矛盾**
  - 现状描述：1、1. 需求文档举例为加法 `(1+2+1+5)=9`；2、2. 数值文档写“累加乘数值”且“引入X1”；3、3. 数值文档流程又写“先随机次数，最后一次必为空”。加法/乘法、独立随机/固定次数互相矛盾。；4、需求文档（段落19）举例RESPIN累加为加法 `(1+2+1+5)=9`；5、而数值文档（段落43）写“累加乘数值”，且流程总结（段落61）写“先随机次数，最后一次必为空”。加法/乘法、独立随机/固定次数在三处描述中互相矛盾。
  - 证据来源：疯狂777需求文档修改后.docx / 段落19；crazy777数值文档修改后.docx / 段落43-46, 61；疯狂777需求文档修改后.docx / 段落19；crazy777数值文档修改后.docx / 段落43, 61
  - 风险分析：核心结算链路无法实现，RTP无法计算，直接阻塞开发与测试。

## 三、核心测试点建议
### 功能验证
- 验证123列中奖且第4列中间为RESPIN时，是否正确触发RESPIN玩法。
- 验证RESPIN玩法中，每次重转的乘数累加逻辑（加法/乘法）及遇空终止逻辑。
- 验证基础盘面生成时，混合符号（如2个bar+1个7）的赔付类型匹配是否正确。
- 验证推展机制触发时，盘面表现与最终结算金额是否一致。
- 验证自动旋转在触发RESPIN后的停止时机是否符合预期。
### 异常操作
- 验证RESPIN过程中断线重连，是否能正确恢复RESPIN状态及累计乘数。
- 验证RESPIN过程中快速点击旋转按钮，是否被正确拦截。
- 验证钱包余额不足时，点击旋转是否正确拉起充值弹窗。
### 兼容性
- 验证不同分辨率下，中奖金额缩位展示（K/M）是否溢出或截断异常。
- 验证快捷旋转模式下，RESPIN累加动画是否卡顿或表现异常。
### 安全专项
- 验证风控拦截（超过100倍强制0倍）时，服务端是否正确下发0倍结算，客户端表现是否一致。
- 验证重复点击旋转按钮，服务端是否保证幂等性，不重复扣款。
### 回归影响
- 验证基础单线中奖逻辑是否受RESPIN和推展机制新增代码的影响。
- 验证自动旋转、快捷旋转等通用功能在新增RESPIN表现后是否稳定。
### 性能与稳定性
- 验证RESPIN连续触发多次（如10次以上）时，客户端内存和帧率是否稳定。
- 验证推展机制表演动画是否会导致客户端短暂卡顿。
### 用户体验
- 验证中奖金额缩位展示（如15555显示15.55K）是否符合向下取整规则。
- 验证RESPIN触发时，第4列图案与中间中奖线的视觉对齐是否清晰。
