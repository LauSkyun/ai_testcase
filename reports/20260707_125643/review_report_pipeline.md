# 需求文档分析报告

## 一、总体评价
文档整体描述了疯狂777的基础玩法与UI框架，主流程基本可理解。但核心特殊玩法（RESPIN）在需求与数值文档中存在触发条件、计算公式的跨文档冲突，且风控机制与特殊玩法的结算时序未定义，存在多处前后矛盾的表述。

- **文档质量评分：** C
- **评分原因：** 主流程可理解，但核心玩法（RESPIN触发条件、计算公式）存在跨文档冲突，风控与特殊玩法的时序未定义，且存在多处前后矛盾的表述，需补充澄清后方可完整开工。

## 优先处理事项
- **[高] 风控强制0倍与RESPIN结算时序冲突**
  - 责任建议：数值策划
  - 处理原因：若在RESPIN后检查，玩家经历完整的RESPIN动画后被告知因风控赔付为0，体验极差且逻辑上需要回滚；若在RESPIN前检查，则无法准确预估最终累加倍数。；测试无法确定RESPIN的最大次数和最大乘数边界，无法设计极端情况下的性能与内存泄漏测试用例。
- **[高] 空白符号（0倍）赔付规则自相矛盾**
  - 责任建议：系统策划
  - 处理原因：基础结算逻辑存在根本性矛盾。若基础盘面有空符号，到底是赔付0还是赔付1倍（即退还本金）？会导致基础玩法结算错误。；核心玩法逻辑与结算公式不一致，直接阻塞开发实现与测试验收。
- **[高] 第4列（特殊轴）盘面结构与结算行定义模糊**
  - 责任建议：系统策划
  - 处理原因：客户端UI布局与服务器结算逻辑脱节，若第4列为3行，上下行符号是否参与推展表演或结算未定义，导致开发无法确定碰撞范围与表现逻辑。；UI布局与碰撞范围无法确定，导致客户端表现与服务器结算逻辑脱节。

## 三、核心测试点建议
### 功能验证
- 验证基础盘面123列全不为空且第4列为RESPIN时，正确触发RESPIN玩法。
- 验证RESPIN期间乘数累加逻辑（初始1+后续累加和）与最终奖金计算公式的正确性。
- 验证推展机制在结算倍数>N且概率命中时，正确播放先低后高的表演动画，且最终结算金额正确。
- 验证风控机制在基础赔付或RESPIN累加后超过100倍时，正确强制为0倍。
### 异常操作
- 验证RESPIN动画播放过程中断线重连，能否正确恢复至最终结算状态。
- 验证RESPIN期间快速点击自动旋转按钮，状态机是否正常，不会导致死锁或重复触发。
- 验证基础盘面有空符号时，正确判定为0倍赔付，不触发RESPIN。
### 兼容性
- 验证不同分辨率下，第4列特殊轴（尤其是推展上下方符号）的UI适配与遮挡情况。
- 验证金额缩位展示（K/M）在不同语言环境或极端数值下的截断与取整正确性。
### 安全专项
- 验证客户端修改本地配置或内存数据，无法改变服务端下发的最终结算金额与RESPIN累加结果。
- 验证推展表演机制中，客户端仅负责表现，最终金额严格以服务端下发为准。
### 回归影响
- 验证自动旋转、快捷旋转等基础功能在引入RESPIN和推展机制后，原有逻辑未受影响。
- 验证排行榜、中奖记录等公共模块在新增玩法后的数据记录准确性。
### 性能与稳定性
- 验证RESPIN达到最大配置次数（如10次）时，客户端动画播放与内存占用是否稳定，无泄漏。
- 验证连续多次触发推展机制时，客户端渲染性能是否平稳。
### 用户体验
- 验证快捷旋转模式下，RESPIN累加动画的播放速度与表现是否符合预期。
- 验证推展机制触发时，是否有足够的视觉/音效引导，避免玩家误解。
