# 需求文档分析报告

## 一、总体评价
文档整体描述了Racing玩法的核心循环、干预逻辑和UI交互，主流程基本可理解。但核心数值模型存在严重的跨文档冲突（赔率公式不一致），且关键开奖参数（Luck、地形/车型概率）缺失，假数据与服务端结算的边界未隔离，存在较高的经济与结算风险。

- **文档质量评分：** C
- **评分原因：** 主流程可理解，但赔率计算模型跨文档冲突、开奖时间T时序矛盾、核心随机参数Luck缺失等高风险问题直接阻塞核心结算链路的开发与测试，需补充数值配置与边界规则后开工。

## 优先处理事项
- **[高] 赔率计算模型跨文档严重冲突及真假赔率展示歧义**
  - 责任建议：数值策划
  - 处理原因：两套完全不同的赔率模型会导致开发无法实现，且若客户端展示假赔率而服务端按真赔率结算，将引发严重客诉和经济事故。；下注阶段无法获取“实际消耗秒数”，导致赔率公式在下注阶段无法求值，实时赔率功能无法实现。；该问题可能导致开发、配置或测试对“赔率计算模型跨文档严重冲突及真假赔率展示歧义”采用不一致口径。
- **[高] Luck（随机扰动）参数完全缺失**
  - 责任建议：数值策划
  - 处理原因：Luck直接决定比赛时长和动画表现，缺失该参数导致开奖时间无法计算，比赛动画无法配置，核心玩法无法落地。
- **[高] 假数据（人数/金额）与服务端结算逻辑的边界未隔离**
  - 责任建议：系统策划
  - 处理原因：若服务端使用假数据进行奖池计算和开奖干预，将导致经济模型崩溃和赔付失控；若仅客户端展示假数据，需明确声明以防开发误用。

## 二、逐维度问题清单
### 【清晰度与完整性】
- **[严重程度：中] MAX下注与单选项上限（100万）的截断逻辑缺失**
  - 现状描述：下注档位包含MAX（消耗所有余额），同时规定单个选项单轮次最多下注100万宝石，但未定义余额大于上限或已下注部分金额后点击MAX的处理逻辑。；文档未明确玩家下注后，宝石是立即扣除（冻结），还是开奖后结算扣除。；奖池状态定义公式为“((今日+昨日收入)-(今日+昨日支出))/(今日+昨日收入)”，若今日和昨日总收入为0（如刚开服或无人下注），分母为0。
  - 证据来源：musee游戏Racing.docx / 3.3下注部分 段落32；musee游戏Racing.docx / 3.3下注部分 全文；musee游戏Racing.docx / 3.4开奖逻辑 段落39
  - 风险分析：前端交互和后端校验逻辑不明确，可能导致超卖或UI显示异常。；若开奖后扣除，可能导致玩家余额不足时超卖；若立即扣除，需明确断线重连、结算中退出时的资产恢复规则。；导致服务端计算报错或崩溃，影响全局开奖逻辑。
  - 修改建议：明确MAX按钮的截断规则，例如“MAX实际下注额 = min(当前余额, 100万 - 该选项已下注额)”，并补充相应的UI提示文案。；明确“下注即冻结/扣除”的时机，并补充断线重连、局内退出时的资产回滚或保留规则。；补充分母为0时的默认处理逻辑（如直接判定为“奖池待补充”或赋予默认状态值）。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：中] 车型与地形生成概率配置缺失**
  - 现状描述：需求文档描述“每个地形都有2个车型出现的概率会高一点”、“两个隐藏地形开启各地形的概率是均等的”，但未提供具体概率数值。；段落44给出了“奖池充裕”时隐藏地形的概率分布，但段落47仅说明“奖池正常”时“均等”，未给出“待补充”状态下的概率，也未给出“均等”的具体数值。
  - 证据来源：musee游戏Racing.docx / 3.3下注部分 段落27；3.4开奖逻辑 段落47；musee游戏Racing.docx / 3.4开奖逻辑 段落44、47、49
  - 风险分析：“高一点”、“均等”无法转化为代码逻辑和配置表，导致开发无法实现。；测试无法验证不同奖池状态下的地形分布是否符合预期。
  - 修改建议：提供具体的车型生成概率配置表（如地形A下，车型X概率30%，车型Y概率30%，其他均分）和隐藏地形均等概率的具体数值（如各20%）。；补充“奖池正常”和“奖池待补充”状态下的隐藏地形概率配置表，明确“均等”的具体百分比（如各20%）。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发

  - 修改建议：补充Luck参数的配置表，明确其取值范围（如0.9~1.1）、分布概率，以及在不同奖池状态/干预逻辑下的调整规则。

  - 现状描述：需求文档定义实时赔率为“合计下注/本选项下注*[001]%”（彩池模型），且明确“实际赔率时也按这个赔率去赔付”；但数值文档给出的公式为“Odds_X = (T * (1 - r) / W_X) * γ”（独立权重模型），并提到“分实际赔率和假赔率”。；需求文档定义T为“实际消耗的秒数”（开奖后产生），但赔率公式需要在下注阶段（开奖前）实时展示给玩家。；需求文档定义实时赔率为“合计下注/本选项下注*[001]%”（彩池模型），且明确“实际赔率时也按这个赔率去赔付”；但数值文档给出的公式为“Odds_X = (T * (1 - r) / W_X) * γ”（独立权重模型），并提到“分实际赔率和假赔率”。两套模型完全不一致，且涉及真假赔率展示歧义，直接导致开发无法实现核心结算逻辑。
  - 证据来源：musee游戏Racing.docx / 3.3下注部分 段落28；Racing数值文档.docx / 段落5、图片1；musee游戏Racing.docx / 3.4开奖逻辑 段落36；Racing数值文档.docx / 图片3；['musee游戏Racing.docx / 3.3下注部分 段落28', 'Racing数值文档.docx / 段落5、图片1']
  - 风险分析：两套完全不同的赔率模型会导致开发无法实现，且若客户端展示假赔率而服务端按真赔率结算，将引发严重客诉和经济事故。；下注阶段无法获取“实际消耗秒数”，导致赔率公式在下注阶段无法求值，实时赔率功能无法实现。；该问题可能导致开发、配置或测试对“赔率计算模型跨文档严重冲突及真假赔率展示歧义”采用不一致口径。

## 三、核心测试点建议
### 功能验证
- 下注流程：各档位下注、MAX截断逻辑、单选项100万上限校验。
- 开奖流程：不同奖池状态下的干预逻辑触发与结果验证。
- 赔率展示：实时赔率计算与结算赔付的一致性验证。
- 排行榜与统计：胜率、赔率、今日/周榜数据更新与排序。
- 新手引导：5步引导流程的交互与倒计时自动跳转。
### 异常操作
- 断线重连：下注后断线、开奖中断线重连后的资产与状态恢复。
- 余额不足：下注时余额不足、MAX下注时余额小于上限。
- 重复点击：下注阶段连续快速点击下注按钮的幂等性。
- 除零异常：奖池收入为0时的状态计算。
### 兼容性
- 全屏/半屏切换：UI布局适配、按钮保留、音频保持。
- 不同分辨率：车辆卡片、排行榜、结果弹窗的UI适配。
### 安全专项
- 假数据隔离：验证服务端结算、奖池计算、干预逻辑是否严格使用真实数据。
- 防篡改：客户端修改下注金额、赔率展示的服务端校验。
- 幂等性：重复提交下注请求的处理。
### 回归影响
- 奖池状态切换：从充裕到正常、待补充的临界点验证。
- 干预逻辑触发：新用户/流失用户判定条件与干预效果。
### 性能与稳定性
- 高并发下注：下注阶段最后几秒的并发请求处理。
- 排行榜刷新：大量用户下注时排行榜的更新性能。
### 用户体验
- 引导流畅度：蒙层引导的文案、高亮、倒计时体验。
- 结果弹窗：中奖/未中奖的反馈、TOP3用户展示、昵称过长截断。
- 信息反馈：下注成功/失败的提示、余额不足提示。
