# 需求文档分析报告

## 一、总体评价
文档描述了3x3+1x3的单线SLOTS玩法及RESPIN累加机制，主流程基本可理解。但核心数值概率权重未区分全局与条件概率导致RTP无法核算，RESPIN累加公式存在歧义，且缺失最大赔付上限与推展机制的结算边界，存在较高的结算与爆仓风险。

- **文档质量评分：** C
- **评分原因：** 主流程可理解，但存在RTP无法核算、RESPIN公式歧义、缺失MAX_WIN及推展结算边界模糊等多个高风险缺口，需补充数值与结算规则后再开工。

## 优先处理事项
- **[高] 基础盘面与乘数轴权重未区分全局/条件概率，RTP无法核算**
  - 责任建议：数值策划
  - 处理原因：数值模型无法成立，RTP无法核算，上线后必然导致严重资损或玩家体验极差。
- **[高] RESPIN公式在需求与数值文档中表述不一致**
  - 责任建议：待定
  - 处理原因：程序和测试在不同文档中看到不同的公式逻辑，可能导致实现与验收标准分裂。；程序无法确定RESPIN的最终乘数计算公式，可能导致结算金额与策划预期不符，引发客诉或资损。；测试无法设计断线重连的验收用例，可能导致玩家重连后看到错误的动画或金额，引发客诉。；缺乏最大赔付兜底，极端情况下（如连续RESPIN高倍）可能导致单局赔付金额超出系统承载或业务预算，造成重大资损。；前端交互逻辑不明确，可能导致自动旋转在RESPIN阶段卡死或表现异常。
- **[高] RESPIN次数与乘数符号权重概率未定义，影响RTP核算**
  - 责任建议：待定
  - 处理原因：该问题会直接影响开发和测试落地。
  - 问题来源：副评审补充 (deepseek-v4-pro)

### 【逻辑一致性与数值平衡】
- **[严重程度：高] 基础盘面与乘数轴权重未区分全局/条件概率，RTP无法核算**
  - 现状描述：1、基础盘面（表2）和乘数轴（表4）的所有结果出现权重均配置为100。若此为全局概率，则基础中奖率高达88.8%，RESPIN触发率高达16.6%，RTP将远超100%；2、若为条件概率，则未说明前置条件。
  - 证据来源：crazy777数值文档修改后.docx / 表格2、表格4
  - 风险分析：数值模型无法成立，RTP无法核算，上线后必然导致严重资损或玩家体验极差。
  - 修改建议：1、明确表2和表4的权重是“全局掉落权重”还是“中奖/触发后的条件权重”。若是全局权重，需重新配置符合RTP目标的概率分布；2、若是条件权重，需补充前置触发条件的说明。
  - 关注角色：数值策划

- **[严重程度：低] 推展机制的“表演”与“真实结算”边界模糊，与风控规则存在潜在冲突**
  - 现状描述：文档描述推展机制为“先得到最终结果盘面，再进行一次表演”，但举例中“先让盘面为5倍+空...而后必定推展X10为最终结果”暗示推展改变了真实结果。未明确推展是纯客户端表现，还是服务端真实修改了结算数据。

  - 风险分析：1、若推展改变真实结果，可能与“超过100倍强制0”的风控规则产生冲突；2、若为纯表现，则举例描述会误导程序实现。
  - 修改建议：明确推展机制是“纯客户端表演（不影响服务端结算数据）”还是“服务端真实修改结果”。若是前者，需补充客户端表现与真实结算不一致时的处理逻辑（如断线重连）。
