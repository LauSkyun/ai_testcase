# 需求文档分析报告

## 一、总体评价
核心玩法循环可理解，但开奖数值模型、赔率显示一致性、机器人匹配规则和关键验收标准缺失较多，导致开发、测试和结算正确性存在显著风险，需补充后才能稳定开工。

- **文档质量评分：** C
- **评分原因：** 主流程可跑通，但赔率口径矛盾、开奖策略与基础概率映射不清、机器人逻辑缺失、排行榜边界未定义，存在多个高风险实现阻塞点。

## 优先处理事项
- **[高] UI 展示赔率、规则文案与配置赔率冲突（3X vs 2.9X）**
  - 责任建议：系统策划/数值策划
  - 处理原因：玩家看到3倍回报，实际结算按2.9倍，引发投诉和退款风险，且验收时无法确认最终表现。；数值平衡基于 2.9 计算，但玩家以 3 倍预期下注，若实际赔付低于预期，会引发投诉。；玩家认为回报率高于实际，产生负面体验和投诉。；未中奖玩家可能以为动画缺失或卡顿。
- **[高] 未定义奖池充裕/正常/回收状态下的实际开奖概率分布，无法验证 RTP**
  - 责任建议：数值策划
  - 处理原因：无法计算理论返还率，可能导致奖池严重透支或过度回收，产生经济事故。；无法计算出每局各选项的真实开出概率，筹码分配、赔率与奖池平衡无法验证，RTP 模型缺失，可能导致严重经济风险。；当兜底触发时，可能完全忽略基础概率，导致实际开奖结果与玩家预期严重偏离，且缺乏可验证性。；测试无法验证策略是否按预期执行，可能上线后出现逻辑错误。
- **[高] 机器人投放逻辑仅出现在流程图，正文未定义，实现依据不足**
  - 责任建议：系统策划
  - 处理原因：开发无法确定机器人何时触发、如何投入、是否影响奖池和开奖结果，测试无法覆盖，且可能被玩家感知为虚假对局。；扣款时机影响重复投入、余额校验和异常中断恢复逻辑，缺少规则会导致客户端与服务端状态不一致。；异常操作可能导致货币误差或状态卡死，测试无法覆盖。；机器人投入金额可能被恶意利用，导致奖池异常或玩家投诉。

## 三、核心测试点建议
### 功能验证
- 验证所有 UI 赔率显示统一为 2.9X
- 构造奖池收益率达到阈值，验证奖池状态切换和对应开奖策略
- 模拟新增用户、亏损大R、预流失用户，验证人群保护触发和开奖偏移
- 验证兜底触发时选择赔付最小选项的逻辑
- 验证排行榜排名展示规则（31-50名）
- 验证 Repeat 按钮在余额不足、已使用后的状态
- 验证投入阶段倒计时结束后未投入的用户是否被强制清空
### 异常操作
- 投入阶段快速切换档位并重复点击同一选项，验证扣款幂等性
- 开奖动画或结算弹窗期间断线重连，验证状态恢复
- 余额不足时点击投入，验证 toast 提示和充值拉起
- 结算弹窗展示5秒内快速关闭，验证是否重复弹窗
### 兼容性
- 半屏/全屏入口切换时，界面布局和交互是否正常
- 不同设备分辨率下，档位、图案区域点击是否准确
### 安全专项
- 验证服务端开奖结果与客户端表现一致，客户端无法篡改
- 验证机器人投入行为由服务端控制，且不影响真实玩家奖池
- 验证广播中奖区间过滤逻辑，防止低额中奖被广播
### 回归影响
- 修改赔率配置后，历史对局记录和开奖分析统计是否受影响（需确认统计口径）
### 性能与稳定性
- 大量并发投入时，奖池状态计算和开奖判定是否超时
- 每局最多20条跑马灯消息传输的压力测试
### 用户体验
- 新手引导步骤是否与新 UI 一致，赔率显示是否为 2.9
- 未中奖时结算弹窗的视觉反馈是否自然
