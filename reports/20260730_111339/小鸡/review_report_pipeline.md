# 需求文档分析报告

## 一、总体评价
需求文档描述了休闲博弈玩法的核心循环，但碰撞机制在需求侧与数值侧存在根本性矛盾，导致主流程无法直接实现。同时难度映射、超级大奖、扣款时机等关键规则缺失，异常处理和安全性说明不足，需大幅澄清后才可开发。

- **文档质量评分：** D
- **评分原因：** 核心碰撞机制在需求文档（车辆碰撞检测）与数值文档（预设爆炸倍数）间存在不可调和的冲突，无法形成一致实现方案。

## 优先处理事项
- **[高] 难度与概率、倍率池的映射关系无法对应**
  - 责任建议：数值策划
  - 处理原因：程序无法确定每个难度下的实际概率和倍率取值，配置表无法落地。；无法实现通关结算逻辑，影响核心循环闭环。

## 二、逐维度问题清单
### 【清晰度与完整性】
- **[严重程度：高] 难度与概率、倍率池的映射关系无法对应**
  - 现状描述：1、需求文档表格2（小鸡.docx 3.1下注系统）中，简单难度列出了四行：20%概率/1.03x倍率、35%/1.07x、50%/1.12x、65%/1.17x；2、数值文档（小鸡数值文档 表格2、表格3）明确定义四个难度对应24/62/103/176倍盘，各有30个格子赔率，并无上述概率-倍率范围。；3、需求文档（小鸡.docx 2.1节）提到成功通过所有预设马路触发「超级大奖」，获得额外高额奖励，但未给出奖励金额、倍率或计算公式。
  - 证据来源：小鸡.docx / 表格2（下注系统）；小鸡数值文档 / 表格2、表格3；小鸡.docx / 2.1 完整游戏流程 通关阶段
  - 风险分析：1、程序无法确定每个难度下的实际概率和倍率取值，配置表无法落地。；2、无法实现通关结算逻辑，影响核心循环闭环。
  - 修改建议：1、重新定义难度与概率、倍率表的映射关系，建议以数值文档的30格赔率表为准，删除需求文档中混乱的示例数据。；2、补充超级大奖的奖励规则，例如固定金额、基于总下注的倍数加成，或与最后一格倍率挂钩。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：中] 碰撞/失败判定机制在需求文档与数值文档间存在根本冲突**
  - 现状描述：1、需求文档（小鸡.docx 3.2节）描述为：车辆随机刷新，骆驼与车辆碰撞盒重叠即判定失败；2、数值文档（小鸡数值文档 4.撞击概率计算）描述为：类似火箭CRASH，先随机爆炸倍数，结合必爆概率决定在哪一格失败，无实时碰撞检测。；3、需求文档描述玩家选择下注筹码后点击「开始」进入游戏，但未说明是否在此时扣除下注金额。失败时「所有奖金清零」，未明确下注本金是否算作奖金的一部分。；4、需求文档示例为3,5,10,20；5、数值文档示例为100,1000。
  - 证据来源：小鸡.docx / 3.2 移动与碰撞系统；小鸡数值文档 / 4. 撞击概率计算；小鸡.docx / 2.1 完整游戏流程、3.3 奖金计算系统；小鸡.docx / 表格1；小鸡数值文档 / 表格1；小鸡.docx / 图片1、2、3、4、5、6、7；小鸡.docx / 3.4 失败结算；模型未提供可核验的原文定位，采用该结论前需回查需求文档。

  - 修改建议：1、统一为服务端预先生成爆炸倍数的模式，客户端仅做表现，移除车辆碰撞检测的描述；2、或明确采用碰撞检测，并重新设计数值模型。；3、明确在点击「开始」前扣除下注金额，总奖金公式包含本金，失败时已扣除的本金不返还，不再额外扣款。；4、统一使用一套示例，并明确说明各业务可自定义。；5、补充首次进入游戏时的引导流程，包括筹码选择、开始、提现操作演示。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞测试用例设计

## 三、核心测试点建议
### 功能验证
- 验证各难度下爆炸倍数生成与赔率表一致
- 验证提现时总奖金等于下注金额×已通过格子赔率累积
- 验证通关超级大奖触发和奖励金额
- 验证下注扣款在点击开始前完成
- 验证失败时奖金清零
- 验证提现确认框取消后游戏继续
- 验证「再来一局」按钮重置状态
### 异常操作
- 快速连续点击「开始」按钮，验证只触发一次前进
- 快速连续点击「提现」按钮，验证只到账一次
- 提现请求过程中强退游戏，重进验证奖金到账
- 游戏中断线重连，验证恢复至最后状态或失败
- 在确认框中侧滑返回，验证游戏状态不变
### 兼容性
- 配置热更后，进行中游戏不受影响，新局使用新配置
- 不同版本客户端与服务端协议兼容
### 安全专项
- 验证随机结果由服务端下发，客户端无法篡改
- 验证扣款、发奖接口幂等，重复请求不重复处理
- 验证客户端无法伪造爆炸点或通过关卡
### 回归影响
- 修改难度赔率表后，验证已有玩法逻辑不受影响
- 修改下注列表后，验证UI显示和扣款正常
### 性能与稳定性
- 大量并发请求时，随机数生成和结算延迟在可接受范围
- 长时间游戏内存占用稳定
### 用户体验
- 验证倍率跳动动画与奖金实时更新一致
- 验证失败提示与再来一局按钮出现时机
- 验证新手引导强制性与可跳过
