# 需求文档分析报告

## 一、总体评价
文档整体框架完整，核心玩法循环和特色机制（重转、推展、免费）的视觉与交互描述较为详细。但需求文档与数值文档在底层盘面生成逻辑、符号定义映射以及风控与封顶规则上存在致命冲突，且部分核心数值（如购买免费、大奖阈值）缺失，需优先对齐并补充后方可进入开发。

- **文档质量评分：** C
- **评分原因：** 主玩法底层生成逻辑与基础中奖规则存在致命冲突，且风控规则与最高赔率/封顶规则自相矛盾，跨文档一致性问题阻塞主流程实现，需补充并对齐后再完整开工。

## 优先处理事项
- **[高] 底层盘面生成逻辑与基础中奖规则存在致命冲突**
  - 责任建议：数值策划
  - 处理原因：主玩法循环无法按需求文档预期跑通，测试无法设计基础中奖用例，开发无法确定最终盘面数据结构。
- **[高] 风控强制0倍与2000倍封顶/最高赔率存在数值模型冲突**
  - 责任建议：数值策划
  - 处理原因：若单局被强制0倍，玩家看到x100与10倍匹配却获得0奖金，体验极差；且免费模式如何累计到2000倍缺乏逻辑支撑，数值模型自相矛盾。；开发无法确定“1”是否代表银行，以及x1的展示样式和逻辑；中奖公式中“符号值”与“乘数”的映射关系模糊。
- **[中] RESPIN触发条件与概率配置存在歧义**
  - 责任建议：数值策划
  - 处理原因：程序无法确定是“满足条件时100%触发但整体盘面概率控制在10%”，还是“满足条件时仅10%几率触发”。

## 二、逐维度问题清单
### 【清晰度与完整性】
- **[严重程度：中] 购买免费游戏核心数值与规则缺失**
  - 现状描述：1、需求文档仅说明OMS后台控制开关和价格系数，未提供购买价格公式、购买后触发的初始免费次数（固定还是随机）、以及是否受风控限制等具体规则。；2、未说明在RESPIN表演、推展动画、免费续杯或购买免费游戏扣款后断线/强退的恢复逻辑。；3、规定了续杯无上限，且总赢奖达2000倍自动结束。但未说明若单局结算后同时达到2000倍且触发续杯，是先结算结束还是先增加次数。
  - 证据来源：钱来了需求文档.docx / 3.5.3 购买免费游戏（段落191-198）；钱来了需求文档.docx / 3.4 特色机制、3.5.3 购买免费游戏；钱来了需求文档.docx / 3.4.3 免费旋转（段落166-168）
  - 风险分析：1、无法进行购买功能的开发、数值配表和测试验收，可能导致经济系统漏洞。；2、可能导致玩家资产丢失、免费次数卡死或状态异常。；3、可能导致结算金额异常或免费次数计算错误。
  - 修改建议：1、补充购买免费游戏的价格公式（如当前投注额的N倍）、初始次数规则、以及购买局的风控策略。；2、补充玩法专属的断线重连规则，明确各阶段中断后的恢复策略（如：购买扣款后断线，重连后直接进入免费游戏）。；3、明确封顶判定的优先级和时序，建议“单局结算后累加，若≥2000倍则立即结束，不再执行续杯”。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：中] 大奖（Big Win等）触发阈值缺失**
  - 现状描述：需求文档提到根据通用倍数显示big win/mega win/super win，但未定义具体的倍数阈值。
  - 证据来源：钱来了需求文档.docx / 2.2 大奖获取界面（段落21-22）
  - 风险分析：开发无法编写判断逻辑，测试无法验收大奖弹窗。
  - 修改建议：明确三个大奖等级对应的具体赢奖倍数阈值（如≥10倍、≥50倍、≥100倍等）。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞测试用例设计
- **[严重程度：中] 推展机制的上下方向与1x3逻辑盘面结构矛盾**
  - 现状描述：逻辑盘面为1x3（1行3列），但需求文档和数值文档均描述推展时中间轴有“上方或下方”的符号。
  - 证据来源：钱来了需求文档.docx / 3.2.1 卷轴结构（段落96）、3.4.2 推展模式（段落159）；钱来了数值文档.docx / 五、推展机制（段落31）
  - 风险分析：若逻辑上只有1行，服务端下发的数据是否包含上下符号信息？客户端表现与服务端数据可能无法对齐。
  - 修改建议：明确推展的“上下”是纯视觉表现还是逻辑数据。若是视觉表现，需说明服务端如何下发推展前的上下符号数据。
  - 关注角色：程序
  - 置信度：中
  - 阻塞级别：阻塞测试用例设计
