# 需求文档分析报告

## 一、总体评价
文档主流程可理解，但仍存在RESPIN结算公式歧义：累加后乘基础奖金 vs 先求和再乘、推展机制与风控强制0倍的互斥与执行顺序未定义、UI赔率表(Paytable)展示数值与后端配置表赔率严重脱节等高风险问题，建议补充对齐后再推进开发与测试。

- **文档质量评分：** C
- **评分原因：** 主流程可理解，但仍存在高风险缺口或关键边界缺失，需要补充后再完整开工。

## 优先处理事项

  - 责任建议：系统策划

## 二、逐维度问题清单
### 【清晰度与完整性】
- **[严重程度：高] UI赔率表(Paytable)展示数值与后端配置表赔率严重脱节**
  - 现状描述：1、需求文档UI截图（图片14/18/21）中的奖级表显示777赔率为100000，7为20000/1000等；2、而需求文档表格1与数值文档表格2中，777的赔率倍数为77，7为17。两者数值差异巨大，且未说明UI展示的是“固定奖金”还是“赔率倍数”。
  - 证据来源：疯狂777需求文档修改后.docx / 图片14、18、21；crazy777数值文档修改后.docx / 表格2
  - 风险分析：玩家在游戏内看到的规则赔率与实际结算赔率完全不符，上线后必然引发严重客诉、退款及合规风险。
  - 修改建议：1. 若UI展示的是“赔率倍数”，需将图片中的数值修改为与配置表一致（77, 37, 17等）；2. 若UI展示的是“固定奖金”，需在需求文档中补充“基础投注档位映射表”，明确不同投注档位下UI赔率表的动态展示逻辑，确保展示值 = 基础投注 × 配置赔率。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：中] 金额缩位展示的“向下取整”与“直接截断”表述存在歧义**
  - 现状描述：需求文档提到“缩位后保留两位小数向下取整展示”，随后又补充“缩位展示是采用‘直接截断’”。
  - 证据来源：疯狂777需求文档修改后.docx / 二、需求描述，段落30
  - 风险分析：在边界值（如15.559）处理上，向下取整（Floor）和直接截断（Truncate）在负数或特定精度下可能产生歧义，导致前后端展示不一致。
  - 修改建议：统一术语为“直接截断保留两位小数（Floor）”，并补充边界值用例（如15.559显示为15.55，15.999显示为15.99）。
  - 关注角色：系统策划
  - 置信度：中
  - 阻塞级别：阻塞测试用例设计

### 【逻辑一致性与数值平衡】
- **[严重程度：高] RESPIN结算公式歧义：累加后乘基础奖金 vs 先求和再乘**
  - 现状描述：1、文档中多个RESPIN相关边界未明确：1）第4列命中respin但123列有空时，盘面如何展示与结算（是展示respin图标但按0倍结算，还是重新随机第4列）；2、2）强制0倍时，第4列是否仍随机乘数符号，若随机到respin或高倍乘数但基础赔率为0，会造成表现困惑；3、3）快捷旋转下RESPIN是快速播放每次累加动画还是直接显示最终结果；4、4）RESPIN中途点击自动旋转/停止按钮的响应。
  - 证据来源：疯狂777需求文档修改后.docx / 段落19、35、36、39、42；crazy777数值文档修改后.docx / 段落21、22、42、45、46、55-56，表格4、表格7
  - 风险分析：前端无法确定RESPIN状态机和盘面生成逻辑，测试无法设计验收用例，易导致交互体验割裂。
  - 修改建议：1. 明确第4列respin但123列空时，走表演权重重新随机第4列，按普通0倍局结算；2. 明确强制0倍时，第4列固定为空白（乘数值1），不展示乘数动画；3. 快捷旋转下RESPIN每次累加直接以2D图快速切换，最终结果弹出，不播放流光/飞行动效；4. RESPIN期间自动旋转按钮置灰，点击无效，需等待RESPIN自然结束。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：中] 推展机制与风控强制0倍的互斥与执行顺序未定义**
  - 现状描述：数值文档规定推展是展示层面的动画（先得到结果再表演），而风控规定超过100倍强制0倍。未说明若真实结果>100倍被风控拦截后，推展动画是否还播放。
  - 证据来源：crazy777数值文档修改后.docx / 段落38-40，段落55-56，段落59
  - 风险分析：若推展动画在风控之后播放，可能出现“动画推展到高倍，但实际结算为0”的严重表现与结算不一致事故。
  - 修改建议：明确流程顺序：推展机制仅作用于风控检查后的“安全结果”。若风控将结果强制为0，则直接跳过推展动画，展示0倍结果。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：中] 风控强制0倍与RESPIN累加过程的交互未定义**
  - 现状描述：风控规则规定超过100倍强制0倍，但未说明是在RESPIN累加过程中实时检查，还是累加完成后最终结算时检查。若累加中途总倍数已超过100倍，是立即终止并强制0，还是继续累加完成后再检查？
  - 证据来源：crazy777数值文档修改后.docx / 段落55-56、段落61
  - 风险分析：1、若累加完成后才检查，可能出现RESPIN展示高倍累加但最终结算为0，造成严重体验事故；2、若实时检查，则需明确中断时机与表现。
  - 修改建议：明确：RESPIN每次累加后实时计算当前总倍数，若超过100倍，立即终止RESPIN，强制本局结果为0倍（123列至少一列空），并跳过后续动画。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
  - 问题来源：副评审补充 (deepseek-v4-pro)

- **[严重程度：低] RESPIN多次重转的结算时机与防篡改边界说明不足**
  - 现状描述：文档提及复用中台风控和断线处理，但未明确RESPIN期间每次重转的结果是服务端实时下发并校验，还是服务端一次性生成完整序列后客户端分步播放。

## 三、核心测试点建议
### 功能验证
- 验证基础局123列全中、部分中、全空的结算正确性。
- 验证RESPIN触发条件（123列全中且第4列为respin）及累加结算公式。
- 验证第4列出respin但123列有空时的盘面展示与结算。
- 验证推展机制的触发概率及动画表现。
- 验证风控强制0倍的触发条件及盘面生成，特别是RESPIN累加超100倍时的处理。
### 异常操作
- RESPIN累加过程中断线重连，验证序列恢复与最终结算。
- RESPIN过程中快速点击自动旋转/停止按钮，验证状态机锁定。
- 余额不足时点击旋转，验证充值弹窗拉起与流程回退。
### 兼容性
- 不同分辨率下奖级表（Paytable）的翻页与截断显示。
- 金额缩位展示（K/M/B）在各级别分辨率下的对齐与截断规则。
### 安全专项
- 抓包验证RESPIN重转序列是否由服务端一次性下发，客户端无法篡改累加次数。
- 验证重复点击旋转按钮的幂等性，确保不重复扣款。
### 回归影响
- 验证中台通用风控模块对本游戏特殊符号（如respin、空）的兼容性。
- 验证排行榜、中奖记录等公共模块的数据上报准确性。
### 性能与稳定性
- RESPIN连续触发（如连续10次以上）时的客户端内存与帧率表现。
- 快捷旋转模式下，高频2D图切换的渲染性能。
### 用户体验
- 新手引导对单线中奖及RESPIN机制的解释清晰度。
- 未中奖时的视觉与音效反馈是否明确。
- 金额缩位展示（如15.55K）的玩家理解成本。
