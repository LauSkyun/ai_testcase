# 需求文档分析报告

## 一、总体评价
文档描述了疯狂777的核心SLOTS玩法与RESPIN特殊机制，主流程基本可理解。但核心结算公式、概率模型定义、推展触发条件存在多处逻辑冲突与口径不一致，且缺乏RTP、最大赔付等关键数值边界，UI展示与底层配置严重脱节。

- **文档质量评分：** C
- **评分原因：** 主流程可理解，但RESPIN累加公式、空符号概率定义、推展触发条件存在高风险逻辑冲突，且缺乏RTP与最大赔付约束，需补充修正后方可进入开发。

## 优先处理事项
- **[高] RESPIN结算公式与累加逻辑跨文档表述冲突**
  - 责任建议：数值策划
  - 处理原因：服务端结算代码与客户端展示金额将出现严重偏差，导致经济事故。
- **[高] 基础盘面“空”符号定义重叠导致概率模型失效**
  - 责任建议：数值策划
  - 处理原因：服务端无法根据当前配置生成正确的盘面，RTP和中奖概率完全失控，阻塞核心开奖逻辑开发。
- **[高] 推展机制触发条件“倍数”与“总下注N倍”单位混淆**
  - 责任建议：系统策划
  - 处理原因：程序无法编写推展机制的触发判断逻辑，测试无法验证推展概率和阈值。

## 二、逐维度问题清单
### 【清晰度与完整性】
- **[严重程度：高] 基础盘面“空”符号定义重叠导致概率模型失效**
  - 现状描述：需求文档与数值文档中，ID 0定义为“有空符号出现”，而ID 1（any）的定义中又明确包含“1为空或3为空”的情况。两者在逻辑上存在包含与重叠，且权重均设为100，导致总权重和概率分布无法计算。
  - 证据来源：疯狂777需求文档修改后.docx / 段落10-15、表格1、表格2；crazy777数值文档修改后.docx / 段落9-17、表格2、表格3
  - 风险分析：服务端无法根据当前配置生成正确的盘面，RTP和中奖概率完全失控，阻塞核心开奖逻辑开发。
  - 修改建议：重新定义基础盘面的互斥事件集合。明确ID 0是否为“全空”或“特定空”，并将ID 1-8的定义严格限定为“无空符号”的中奖组合，确保所有ID互斥且权重之和为100%。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：高] 推展机制触发条件“倍数”与“总下注N倍”单位混淆**
  - 现状描述：数值文档描述“当最终结算结果倍数大于总下注N时...默认配置5倍”。举例“5倍+X10”中，“5倍”指代不明。无法确定触发条件是“赔率×乘数 > N”还是“中奖金额 > 总下注 × N”。
  - 证据来源：crazy777数值文档修改后.docx / 段落38-40
  - 风险分析：程序无法编写推展机制的触发判断逻辑，测试无法验证推展概率和阈值。
  - 修改建议：统一公式口径。明确“最终结算结果倍数”是指“基础赔率×乘数符号值”，触发条件应修改为“当（基础赔率×乘数符号值）> N 时触发”，并补充N和M的合法配置范围。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：高] RESPIN结算公式与累加逻辑跨文档表述冲突**
  - 现状描述：需求文档举例明确为加法累加（1+2+1+5=9），而数值文档公式未明确乘数基数，且未将基础投注纳入最终得奖公式，导致两份文档的结算口径不一致。
  - 证据来源：疯狂777需求文档修改后.docx / 段落18-19；crazy777数值文档修改后.docx / 段落30、43-45
  - 风险分析：服务端结算代码与客户端展示金额将出现严重偏差，导致经济事故。
  - 修改建议：在数值文档中统一RESPIN最终结算公式为：最终中奖金额 = 基础投注 × 基础赔率 × (1 + Σ(每次respin获得的乘数值))。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞测试用例设计
- **[严重程度：高] UI赔付表展示数值与底层配置赔率严重脱节**
  - 现状描述：1、需求文档规则弹窗图片中的赔率数值（如100000）与底层配置表中的赔率倍数（77）完全无法映射，图片可能为占位符或计算口径错误。；2、需求文档规则弹窗图片（图片14/18/21）中展示的赔率数值（如777*3对应100000、20000等）与底层配置表（表格1）中的赔率倍数（77、37、17等）完全无法映射。

  - 风险分析：1、玩家看到的规则赔率与实际结算赔率不符，构成严重的欺诈风险。；2、玩家看到的规则赔率与实际结算赔率不符，构成严重的欺诈风险与合规问题。

### 【逻辑一致性与数值平衡】
- **[严重程度：高] RESPIN结算公式与累加逻辑跨文档表述冲突**
  - 现状描述：1、需求文档举例为加法累加（1+2+1+5=9），最终金额=基础投注×基础赔率×累加和。数值文档公式为“中奖金额=基础投注×赔率×乘数符号值”，且说明“累计乘数值默认=1”，未明确RESPIN期间是“相加”还是“相乘”，也未将基础投注纳入最终得奖公式。；2、需求文档说明“RESPIN结算完成后停止”，但未明确如果在RESPIN的多次重转过程中玩家点击停止，是立即中断当前重转动效并结算，还是必须等待所有重转动画播放完毕。；3、数值文档说明respin触发条件是“第4列停在respin且123列均不为空”。但未说明服务端生成盘面时，是独立生成第4列再判断冲突，还是根据123列的结果动态调整第4列的权重池。；4、需求文档仅说明“复用中台统一处理流程”，但RESPIN是一个包含多次重转的多步状态机。未明确断线发生在RESPIN第N次重转时，重连后是直接展示最终结算结果，还是从断点继续播放动画。；5、需求文档说明快捷旋转下RESPIN表现为“快速播放累加动画”，但未定义单次快速动画的时长或总时长上限。
  - 证据来源：疯狂777需求文档修改后.docx / 段落18-19；crazy777数值文档修改后.docx / 段落30、43-45；疯狂777需求文档修改后.docx / 段落35；crazy777数值文档修改后.docx / 段落22、42；疯狂777需求文档修改后.docx / 段落20；疯狂777需求文档修改后.docx / 段落36；crazy777数值文档修改后.docx / 表格6、表格7、段落47-48
  - 风险分析：1、服务端结算代码与客户端展示金额将出现严重偏差，导致经济事故或玩家客诉。；2、客户端状态机设计存在歧义，可能导致自动旋转停止时表现异常或结算延迟。；3、如果独立生成，当123列有空且第4列为respin时，会导致respin概率被隐性稀释或需要额外的重roll逻辑，影响整体RTP。；4、中台通用流程可能不支持多步状态机的断点恢复，导致重连后表现与结算不一致，或动画卡死。；5、如果RESPIN触发10次，快速动画总时长可能依然过长，违背快捷旋转“节省时间”的初衷。
  - 修改建议：1、在数值文档中统一RESPIN最终结算公式为：`最终中奖金额 = 基础投注 × 基础赔率 × (1 + Σ(每次respin获得的乘数值))`。明确初始1是作为加数基数，而非乘数。；2、明确自动旋转停止的时机：建议定义为“点击停止后，当前正在进行的RESPIN重转动效加速播放或直接跳过，待本次RESPIN结算完成后停止自动旋转”。；3、明确服务端盘面生成算法：建议采用“先生成123列，若全非空则从包含respin的完整权重池抽取第4列；4、若123列有空，则从排除respin的权重池抽取第4列”的条件生成逻辑。；5、明确RESPIN断线恢复策略：建议服务端在RESPIN开始时即计算好最终结果并持久化，客户端重连后直接展示最终盘面和结算金额，跳过中间重转动效。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发

## 三、核心测试点建议
### 功能验证
- 验证RESPIN触发条件（第4列respin且123列非空）及累加乘数计算逻辑。
- 验证推展机制的触发阈值（赔率×乘数 > N）及概率（M）。
- 验证自动旋转在RESPIN过程中的停止时机及表现。
- 验证基础盘面“空”符号的生成概率与互斥逻辑。
### 异常操作
- 验证RESPIN多步状态中断线重连的恢复表现（是否直接展示最终结果）。
- 验证余额不足时的扣款失败处理及充值弹窗拉起。
- 验证风控触发强制0倍时的盘面生成与客户端表现。
### 兼容性
- 验证不同分辨率下金额缩位展示（K/M）的截断逻辑与UI适配。
- 验证规则弹窗、排行榜弹窗在不同屏幕尺寸下的翻页与关闭交互。
### 安全专项
- 验证服务端结算结果与客户端展示金额的强一致性，防止客户端篡改赔率。
- 验证重复点击旋转按钮的幂等性，防止重复扣款。
### 回归影响
- 验证中台通用断线重连流程对本玩法RESPIN状态机的兼容性。
- 验证中台通用风控模块对100倍以上强制0倍逻辑的执行准确性。
### 性能与稳定性
- 验证快捷旋转模式下，RESPIN触发10次时的动画播放帧率与内存占用。
- 验证长时间自动旋转下的内存泄漏与客户端稳定性。
### 用户体验
- 验证新手玩家对RESPIN累加机制的理解度（动效引导是否清晰）。
- 验证中奖金额滚动变化动效的时长（1S）是否影响操作节奏。
