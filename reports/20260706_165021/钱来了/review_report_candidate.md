# 需求文档分析报告

## 一、总体评价
文档主流程可理解，但仍存在RESPIN机制底层“纯表演”逻辑与需求表现严重脱节、购买免费游戏（Feature Buy）核心规则与数值完全缺失、风控“100倍强制0”与“2000倍封顶”存在直接数值冲突等高风险问题，建议补充对齐后再推进开发与测试。

- **文档质量评分：** C
- **评分原因：** 主流程可理解，但仍存在高风险缺口或关键边界缺失，需要补充后再完整开工。

## 优先处理事项
- **[高] RESPIN机制底层“纯表演”逻辑与需求表现严重脱节**
  - 责任建议：系统策划
  - 处理原因：测试用例将基于“真实概率触发”设计，导致抓包、日志核对与底层实际逻辑完全冲突。客户端若按真实概率写触发逻辑，将与服务端结果无法对齐。
- **[中] 购买免费游戏（Feature Buy）核心规则与数值完全缺失**
  - 责任建议：系统策划
  - 处理原因：开发无法实现扣款与发奖逻辑，测试无法设计购买功能的验收用例，存在经济漏洞风险。无法验证“无上限续杯”是否会导致经济崩溃，测试缺乏免费游戏数值体验的验收基准。弱网或断线重连时，客户端可能因丢失表演状态而卡死，或重复发奖。可能导致重复扣款或重复发放免费次数，引发严重经济事故。
- **[高] 风控“100倍强制0”与“2000倍封顶”存在直接数值冲突**
  - 责任建议：数值策划
  - 处理原因：若开发或测试误解为风控控制总赢奖，可能导致免费游戏2000倍封顶逻辑无法实现或测试错误。

## 二、逐维度问题清单
### 【清晰度与完整性】
- **[严重程度：中] 购买免费游戏（Feature Buy）核心规则与数值完全缺失**
  - 现状描述：需求文档仅说明购买免费游戏由后台控制开关和价格系数，但未定义价格计算公式（如基础投注*系数*次数？）、购买后发放的免费次数（固定还是随机5/10/20？）、以及购买行为是否受风控区间限制。数值文档仅说明免费游戏“配置结构基本相同，概率独立配置”，但未提供免费的专属权重表、续杯概率衰减机制或RTP目标。需求文档仅说明免费游戏中断后“继续旋转之前未完成的免费次数”，但未说明若在RESPIN或推展的“表演动画”中途断线，重连后是直接跳过表演展示最终结果，还是重播表演。购买免费游戏涉及直接扣款与发放高价值免费次数，但文档未说明重复点击、弱网重试时的幂等处理，以及购买后若遇风控（如直接触发100倍强制0）的退款/补偿逻辑。
  - 证据来源：钱来了需求文档.docx / 3.5.3 购买免费游戏，段落192-198；钱来了数值文档.docx / 八、免费游戏，段落57-58；钱来了需求文档.docx / 3.5.2 触发流程，段落189；钱来了需求文档.docx / 3.5.3 购买免费游戏，段落196-198
  - 风险分析：开发无法实现扣款与发奖逻辑，测试无法设计购买功能的验收用例，存在经济漏洞风险。无法验证“无上限续杯”是否会导致经济崩溃，测试缺乏免费游戏数值体验的验收基准。弱网或断线重连时，客户端可能因丢失表演状态而卡死，或重复发奖。可能导致重复扣款或重复发放免费次数，引发严重经济事故。
  - 修改建议：补充购买价格公式、购买后发放的免费次数规则（建议明确为固定次数或按权重随机），并明确购买免费游戏是否参与普通/免费风控检查。补充免费游戏内的金币符号与乘数符号权重表，明确续杯概率是否独立或衰减，并提供免费游戏的RTP设计目标。补充异常恢复规则：明确在特色机制表演阶段断线重连后，是直接展示最终结算结果（跳过表演），还是重播表演动画。明确购买接口的幂等性设计（如使用唯一流水号），并补充购买后若触发风控的异常处理流程（如退款或保留购买状态）。
  - 关注角色：系统策划
  - 置信度：高

### 【逻辑一致性与数值平衡】
- **[严重程度：高] 风控“100倍强制0”与“2000倍封顶”存在直接数值冲突**
  - 现状描述：数值文档规定普通/免费游戏风控区间“超过100倍直接强制0倍”，该“100倍”指单次Spin的赔率上限。需求文档规定免费游戏总赢奖达到投注额的2000倍时自动结束，为总赢奖上限。两者分别控制单次和总累计，并不冲突。但文档未明确说明风控的“100倍”是单次Spin赔率，也未说明免费游戏风控是否与普通游戏一致，存在理解偏差风险。
  - 证据来源：钱来了数值文档.docx / 六、基础游戏・体验控制 & 风控，段落47/51及表格8、9；钱来了需求文档.docx / 3.4.3 免费旋转模式，段落168
  - 风险分析：若开发或测试误解为风控控制总赢奖，可能导致免费游戏2000倍封顶逻辑无法实现或测试错误。
  - 修改建议：在需求或数值文档中明确说明“风控100倍”是单次Spin赔率，免费游戏的风控规则与普通游戏一致，并说明2000倍封顶是总赢奖上限，两者独立运作。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：中] 推展机制的“概率触发”与“必定中奖”表述矛盾**
  - 现状描述：1、数值文档给出推展发生几率0.15，但说明“而后必定推展X3为最终结果（即必定中奖）”；2、需求文档则描述为“有机会...尝试匹配出...触发中奖”，暗示推展后可能不中奖。
  - 证据来源：钱来了数值文档.docx / 五、基础游戏・核心机制，段落29-31，表格4；钱来了需求文档.docx / 3.4.2 推展模式，段落159
  - 风险分析：1、玩家预期管理不一致。若推展后100%中奖，需求文档的“尝试”描述会误导客户端表现和测试用例；2、若可能不中，数值文档的“必定”则无法实现。
  - 修改建议：1、统一口径：明确推展触发后是100%转化为中奖，还是仍有概率不中。若100%中奖，修改需求文档的“尝试”表述；2、若可能不中，修改数值文档的“必定”逻辑。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞测试用例设计

## 三、核心测试点建议
### 功能验证
- 验证3轴1行单中奖线的匹配逻辑（左右数值相同，中间不为空）。
- 验证免费旋转的触发、续杯（无上限）及2000倍封顶自动结束逻辑。
- 验证购买免费游戏的扣款、发奖及次数发放逻辑。
- 验证推展机制的触发概率及最终结果转化。
- 验证大奖弹窗的触发阈值及跳过/自动关闭逻辑。
### 异常操作
- 验证免费游戏自动旋转中、RESPIN/推展表演动画中途断线重连的状态恢复。
- 验证购买免费游戏时的重复点击、弱网重试下的幂等性（防重复扣款/发奖）。
- 验证余额不足时的旋转与购买拦截。
### 兼容性
- 验证不同分辨率下3轴1行符号的虚化效果、高度齐平及中奖线对齐表现。
- 验证免费模式与主模式界面切换时的背景颜色、下注区域隐藏/显示逻辑。
### 安全专项
- 抓包验证服务端是否直接下发最终结算结果，客户端是否仅做表演（特别是RESPIN机制）。
- 验证风控机制：单次/累计超过100倍时，是否强制第1列为空（0倍）。
- 验证购买免费游戏接口的防刷与幂等校验。
### 回归影响
- 验证通用模块（货币显示、投注、加速、自动、排行榜、记录）在本游戏中的复用表现。
- 验证配置热更时，历史局（特别是未完成的免费游戏）的处理逻辑。
### 性能与稳定性
- 验证快速旋转模式下，1秒所有卷轴停止旋转的性能与动画流畅度。
- 验证免费游戏连续触发续杯时，内存泄漏及客户端卡顿情况。
### 用户体验
- 验证推展机制的视觉反馈是否与“必定中奖”或“尝试中奖”的逻辑预期一致。
- 验证中奖时钞票合并、NPC拿钞票、倍数数字飞出等动效的节奏与爽感。
- 验证未中奖时滚动信息的匀速移动及切换逻辑。
