### 【逻辑一致性与数值平衡】
- **[严重程度：高] Crash概率模型与离散格子玩法的映射逻辑缺失**
  - 现状描述：1、数值文档套用Crash游戏的“爆炸倍数”连续概率模型，但需求文档玩法是离散的30个格子。文档未说明连续的“爆炸倍数”如何映射到离散格子的胜负判定上。；2、需求文档提及通过所有预设马路触发“超级大奖”并获得额外高额奖励，但数值文档仅给到第30关的常规倍率，无额外奖励配置。；3、需求文档设定每次点击“开始”前进1格，最多需通过30个格子，但未说明是否支持“自动连续前进”或“一键到底”机制。；4、需求文档要求连乘计算（总奖金 = 下注金额 × Π(已通过马路倍率)），但数值文档表格2给出的30关数值（如难度1第30关为23.9）定义不明。若为单格倍率，连乘结果将远超MAX_MUL（24倍）；5、若为累计倍率，则与连乘公式冲突。
  - 证据来源：小鸡数值文档.docx / 4. 撞击概率计算；小鸡.docx / 2.2 详细规则；小鸡.docx / 2.1 完整游戏流程 通关阶段；小鸡数值文档.docx / 3. 难度选择 表格2；小鸡.docx / 2.1 完整游戏流程；小鸡数值文档.docx / 3. 难度选择（30个格子）；小鸡.docx / 3.3 奖金计算系统；小鸡数值文档.docx / 3. 难度选择 表格2；小鸡.docx / 3.1 下注系统 表格2；小鸡数值文档.docx / 3. 难度选择
  - 风险分析：1、核心随机逻辑无法实现，程序无法编写碰撞与胜负判定代码。；2、第30关通关后的额外奖励无公式、无配置，结算链路断裂。；3、玩家需手动点击多达30次，严重违背“轻量无负担”和“快节奏”的定位，影响游戏体验。；4、直接阻塞核心结算公式的实现，可能导致数值崩溃或结算错误。；5、开发无法获取完整的难度配置，无法落地难度系统。
  - 修改建议：1、补充映射算法说明。例如：明确“爆炸倍数”对应的是“累计倍率阈值”，当玩家前进到某一格，其累计倍率超过爆炸倍数时判定失败；2、或明确“爆炸倍数”如何转化为每格的独立碰撞概率。；3、在数值文档中补充“超级大奖”的额外奖励公式（如固定金额、固定倍率或奖池分成），或在需求文档中明确通关即按第30关倍率结算，取消“额外奖励”描述。；4、补充局内操作机制：支持长按“开始”按钮自动连续前进，或增加“自动挑战至第N格”的快捷设置。；5、数值策划需明确表格2中的数值是“单格倍率”还是“到达该关卡的累计总倍率”。若是累计总倍率，需将需求文档公式修改为“总奖金 = 下注金额 × 当前关卡累计倍率”
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发

- 验证服务端是否权威控制碰撞结果与赔率，客户端篡改本地倍率是否影响结算。

### 用户体验
- 验证连续手动点击30次的疲劳度及自动连续机制的可用性。
