# 需求文档分析报告

## 一、总体评价
文档主流程可理解，但仍存在缺乏最大赔付(MAX_WIN)与防刷兜底机制、基础经济参数与概率模型跨文档冲突、倍率公式口径与数值表映射冲突及溢出等高风险问题，建议补充对齐后再推进开发与测试。

- **文档质量评分：** C
- **评分原因：** 主流程可理解，但仍存在高风险缺口或关键边界缺失，需要补充后再完整开工。

## 优先处理事项
- **[高] 缺乏最大赔付(MAX_WIN)与防刷兜底机制**
  - 责任建议：数值策划
  - 处理原因：一旦触发高倍率结算，将导致平台出现灾难性资损事故。
- **[高] 基础经济参数与概率模型跨文档冲突**
  - 责任建议：系统策划
  - 处理原因：1、基础经济参数不一致导致下注与结算模块无法对齐；2、两套概率模型无法兼容，程序无法选择底层随机模型，测试无法编写概率验收用例。
- **[高] 倍率公式口径与数值表映射冲突及溢出**
  - 责任建议：数值策划
  - 处理原因：1、结算公式无法落地；2、千万倍级溢出将导致严重资损事故；3、通关结算逻辑缺失，程序无法实现超级大奖派发。

## 二、逐维度问题清单
### 【清晰度与完整性】
- **[严重程度：高] 倍率公式口径与数值表映射冲突及溢出**
  - 现状描述：1. 公式口径歧义：需求公式为单格倍率连乘（Π(已通过马路倍率)），数值表给出的30关数值（如难度1第30关23.9）语义不明（单格还是累计）。
2. 数值表溢出与MAX_MUL矛盾：数值文档MAX_MUL=176，但难度4第30关累计倍率高达6627万倍，概念严重混淆且存在计算溢出。
3. 超级大奖缺失：需求文档提及通关触发“超级大奖”获得额外高额奖励，但数值文档无此配置，且未说明与第30关倍率的关系。
  - 证据来源：小鸡.docx / 3.3 奖金计算系统、2.1 完整游戏流程；小鸡数值文档.docx / 表格2、表格3
  - 风险分析：1、结算公式无法落地；2、千万倍级溢出将导致严重资损事故；3、通关结算逻辑缺失，程序无法实现超级大奖派发。
  - 修改建议：1. 明确数值表口径，若是累计值需反推单格倍率表；
2. 澄清MAX_MUL在Crash算法中的真实物理意义，修正难度4溢出错误；
3. 明确“超级大奖”是固定金额、额外倍率乘区，还是指代通过第30关的累计倍率奖励，并补充配置。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：高] 基础经济参数与概率模型跨文档冲突**
  - 现状描述：1. 下注筹码不一致：需求文档及UI为3/5/10/20，数值文档示例为100/1000。
2. 概率模型冲突：需求文档定义为固定概率（如简单20%-65%），数值文档采用Crash算法（MAX_MUL+必爆概率），两者底层逻辑互斥。
3. UI概率展示歧义：UI展示固定的“被击中概率”，但底层若为Crash算法，每格概率是动态变化的，无法直接映射。
  - 证据来源：小鸡.docx / 表格1、表格2、图片1-4；小鸡数值文档.docx / 表格1、4. 撞击概率计算
  - 风险分析：1、基础经济参数不一致导致下注与结算模块无法对齐；2、两套概率模型无法兼容，程序无法选择底层随机模型，测试无法编写概率验收用例。
  - 修改建议：1. 统一全局下注筹码配置表，明确最终上线的筹码档位及步长；
2. 召开策划与数值对齐会，统一底层随机算法模型（废弃冲突配置）；
3. 明确UI展示的是“当前格概率”还是“整局存活概率”，并给出与底层Crash算法的换算公式。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：低] 核心角色包装设定矛盾（小鸡 vs 骆驼）**
  - 现状描述：1. 文档段落55说明“先用小鸡形象”，但4.1节又详细规定了“卡通骆驼设计”，且UI截图均为小鸡。
  - 证据来源：小鸡.docx / 4.1 核心形象、段落55、图片1-3
  - 风险分析：美术资产验收标准模糊，可能导致首版资源返工。
  - 修改建议：明确首版上线验收标准（小鸡），并说明骆驼资产的替换触发条件与排期，避免执行歧义。
  - 关注角色：系统策划
  - 置信度：高
