## 优先处理事项
- **[高] RESPIN乘数符号1倍配置及公式定义在两文档中不一致**
  - 责任建议：系统策划
  - 处理原因：1. 开发按需求文档配置将无法实现RESPIN的1倍结果，造成数值逻辑错误。

- **[高] 需求文档缺失推展机制、风控机制、卷轴方案选择和RESPIN乘数表，与数值文档不一致**
  - 责任建议：系统策划

4. 断线恢复细节缺失可能导致不同中台实现行为不一致，影响用户体验。

## 二、逐维度问题清单
### 【清晰度与完整性】
- **[严重程度：高] RESPIN乘数符号1倍配置及公式定义在两文档中不一致**
  - 现状描述：1. 需求文档基础乘数符号表（表格3）无1倍图案，但段落19举例出现1倍结果，且数值文档RESPIN乘数符号表（表格7）包含1倍。
2. 需求文档举例公式为10*10*(1+2+1+5)，未明确区分初始乘数（默认1倍）和旋转出的1倍结果，可能导致理解错误。
3. 需求文档描述快捷旋转时RESPIN表现为“快速播放累加动画”，但实际结算只进行一次，可能造成用户误解为每次旋转都独立结算。
  - 证据来源：疯狂777需求文档修改后.docx / 表格3、段落19、段落36；crazy777数值文档修改后.docx / 表格7。
  - 风险分析：1. 开发按需求文档配置将无法实现RESPIN的1倍结果，造成数值逻辑错误。
2. 开发可能误解累加方式，将初始乘数再次加入旋转结果，导致结算错误。
3. 用户可能认为每次旋转动画都对应一次独立结算，产生投诉。
  - 修改建议：1. 统一乘数符号配置，需求文档补充RESPIN专用乘数表，明确基础游戏和RESPIN各自使用的符号。
2. 在公式说明中明确：最终奖励=基础投注×基础赔率×(1 + 旋转累加乘数值)，其中1为初始乘数，旋转结果中的1倍图案也加入累加。
3. 在动画说明中增加提示，或通过UI明确展示总乘数变化，避免歧义。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞测试用例设计和实现
- **[严重程度：高] 需求文档缺失推展机制、风控机制、卷轴方案选择和RESPIN乘数表，与数值文档不一致**
  - 现状描述：1、1. 需求文档未提及推展机制，数值文档定义了推展的触发条件（结算倍数>总下注N）、概率（万分比M）、服务器处理流程和表演逻辑。；2、2. 需求文档未提及风控区间和强0倍逻辑，也未提及卷轴方案选择；3、数值文档定义了风控区间（倍数≥100时强制0倍）和卷轴方案ID及权重。；4、3. 需求文档缺少RESPIN专用乘数符号表（包含1倍图案），数值文档表格7提供了该表，但需求文档基础乘数表（表格3）无1倍，导致开发可能遗漏配置。；5、4. 需求文档异常断线处理仅说明复用中台统一流程，但未定义恢复后的具体状态机（如动画重播、累计显示等）。
  - 证据来源：crazy777数值文档修改后.docx / 五、推展机制 段落38-40；六、体验控制 段落50-56，表格8、9；四、respin机制 段落42-45，表格7。疯狂777需求文档修改后.docx / 全文无对应内容，段落20。
  - 风险分析：1. 开发可能遗漏推展功能，导致游戏体验与数值设计不符，且后续无法通过验收。
2. 风控和卷轴选择缺失会影响数值控制和线上稳定性，可能造成过大的赔付波动。
3. RESPIN乘数表缺失导致前端缺少1倍图标，配置表缺失，无法正确展示和计算。
4. 断线恢复细节缺失可能导致不同中台实现行为不一致，影响用户体验。
  - 修改建议：1. 在需求文档中补充推展机制的完整描述，包括触发条件、概率配置、服务器处理流程、前端表演步骤以及与特殊倍率回推/下拉效果的关联。
2. 补充风控机制说明，包括强制0倍的条件、表演逻辑，以及卷轴方案选择的方式和配置接口。
3. 在需求文档中增加RESPIN专用乘数符号表（表格7），包含1倍图案及其权重，并明确区分基础游戏与RESPIN的符号配置。
4. 明确RESPIN断线恢复后的具体状态机，包括累计乘数、已转次数、动画重播策略等。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞开发和测试
