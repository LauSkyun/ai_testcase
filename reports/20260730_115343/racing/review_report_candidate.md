## 二、逐维度问题清单
### 【清晰度与完整性】
- **[严重程度：高] 干扰指数如何影响开奖结果未定义**
  - 现状描述：文档描述奖池干预时提供干扰指数（如1.01-1.1），但开奖公式 T = L/(V*K*Luck) 中仅出现 Luck 随机扰动，未说明干扰指数是否等于 Luck 还是通过其他方式影响。奖池充裕时提到“对 supercar 有利的地形，出现的概率更高”，并给出具体概率，但未说明哪些地形对 supercar 有利，也未提供所有车型的有利地形映射表。
  - 证据来源：musee游戏Racing.docx / 段落36、43、44，图片13；Racing数值文档.docx / 图片3
  - 风险分析：干预逻辑无法转化为可实现的算法，开奖结果无法按设计生成。
  - 修改建议：明确干扰指数与 Luck 的映射关系，或说明干预通过调整地形概率实现，并提供完整的地形-车型有利映射表。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：高] 总时间计算机制与胜负判定规则缺失**
  - 现状描述：文档仅给出单段地形的时间公式 T = L/(V*K*Luck)，但比赛使用三段地形（每段100m），未说明如何由三段地形的单段计算总时间，以及如何根据总时间判定胜负（如总时间最短者获胜）。
  - 证据来源：musee游戏Racing.docx / 段落26、36，图片13；Racing数值文档.docx / 图片3
  - 风险分析：无法计算三辆车的比赛总时间，无法判定胜负，开奖结果无法生成。
  - 修改建议：补充总时间计算公式（如 T_total = Σ(L_i/(V_i * K_i * Luck_i))），并明确胜负判定规则（总时间最小的车型获胜）。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
  - 问题来源：副评审补充 (deepseek-v4-pro)
- **[严重程度：中] 奖池状态计算公式可能除零**
  - 现状描述：奖池状态 = (（今日+昨日累计收入）-（今日+昨日累计支出）) /（今日+昨日累计收入），若累计收入为 0，则除零。
  - 证据来源：musee游戏Racing.docx / 段落39
  - 风险分析：服务端计算异常。
  - 修改建议：增加对累计收入为 0 时的处理规则，例如默认奖池正常。
  - 关注角色：程序
  - 置信度：高
  - 阻塞级别：阻塞测试用例设计
- **[严重程度：低] 下注扣款时机未说明**
  - 现状描述：文档仅描述下注行为和结果返奖，未说明下注时是否立即扣款，还是开奖时扣除。
  - 证据来源：musee游戏Racing.docx / 段落32-34
  - 风险分析：影响余额校验、重进恢复和异常处理流程。
  - 修改建议：1、明确扣款时机：下注即扣款，并记录未开奖订单；2、开奖后根据结果增加或扣除。
  - 关注角色：系统策划
  - 置信度：中
  - 阻塞级别：建议优化

### 【逻辑一致性与数值平衡】
- **[严重程度：高] 赔率计算、展示与赔付存在多重冲突**
  - 现状描述：1、1. 需求文档实时赔率公式 = 合计下注/本选项下注 * [001]%，保留两位向下取整，直接用于赔付；2、数值文档 odds = max( T*(1-x)/W, 1.02 )，引入 gamma 系数和假赔率，两套公式冲突。2. 数值文档提到“分实际赔率和假赔率”，但需求文档未提及假赔率，UI 展示的赔率使用哪种口径未定义。3. 需求文档定义了假人数和假金额（段落22-23），但实时赔率公式中的“合计下注”未指明是否包含假数据，若包含将导致展示赔率失真，且与真实赔付计算不一致。
  - 证据来源：musee游戏Racing.docx / 段落22-23、28；Racing数值文档.docx / 段落2-5、图片1-2
  - 风险分析：1、实现时无法确定赔付计算逻辑，可能造成结算错误；2、若 UI 展示假赔率而用户按此计算赔付，将导致严重投诉；3、假数据若参与赔率计算会进一步混淆展示与赔付。
  - 修改建议：1、统一赔率计算公式，明确抽水率 r 或 [001]% 的值，决定是否使用 gamma 系数，并说明假赔率的生成与展示规则；2、明确赔率计算和展示仅使用真实下注数据，假数据仅用于氛围展示。

  - 阻塞级别：阻塞开发
