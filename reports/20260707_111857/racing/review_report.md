# 需求文档分析报告

## 一、总体评价
文档描述了赛车竞猜的主玩法循环与干预逻辑，但核心赔率公式在需求与数值文档中存在严重冲突，且缺乏极端下注下的赔付熔断机制与假赔率展示映射。

- **文档质量评分：** C
- **评分原因：** 核心赔率公式在两份文档中互相矛盾，且缺乏最大赔付上限与假赔率展示映射，存在结算歧义与经济事故风险，需补充后再开工。

## 优先处理事项
- **[高] 核心赔率计算公式在需求与数值文档中存在严重冲突**
  - 责任建议：待定
  - 处理原因：需求文档采用“总注/本注*抽水%”的彩池赔率模型，而数值文档采用基于完成时间T和gamma系数的固定/动态赔率模型。两套公式底层逻辑完全不同，开发无法确定使用哪套公式，直接阻塞核心结算链路。
- **[高] 极端下注下的赔付熔断与最大赔付上限缺失**
  - 责任建议：数值策划
  - 处理原因：在极端情况下，赔付金额可能远超系统承受范围，导致严重经济事故。
- **[高] 开奖干预逻辑优先级与参数映射歧义**
  - 责任建议：系统策划
  - 处理原因：服务端无法准确落地干预参数，可能导致干预逻辑失效或产生非预期的开奖结果，影响平台营收与用户体验。；描述与UI表现存在理解歧义，影响动画表现与开奖逻辑开发，可能导致客户端表现与服务端开奖结果不一致。

- **[严重程度：高] “假赔率”机制的UI展示与真实结算映射缺失**
  - 现状描述：1、数值文档明确提出“分实际赔率和假赔率”，但需求文档仅描述了基于下注金额计算的“实时赔率”，未说明UI上展示的是哪种赔率。；2、下注人数和金额需乘系数（如1.35）展示假数据。未明确声明服务端在计算真实赔率或开奖干预时，是否严格剔除了假数据。
  - 证据来源：Racing数值文档.docx / 段落5；musee游戏Racing.docx / 3.3下注部分 段落28；musee游戏Racing.docx / 3.3下注部分 段落22-23

  - 关注角色：系统策划
