  - 证据来源：疯狂777需求文档修改后.docx / 二、需求描述，段落10-13；crazy777数值文档修改后.docx / 二、基础游戏・基础符号，段落10-13

  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：中] 乘数符号“0”与“空白”图案定义混淆**
  - 现状描述：数值文档说明ID=0为空白且乘数为1，但配置表中“乘数符号”列写为“0”。
  - 证据来源：crazy777数值文档修改后.docx / 三、基础游戏・乘数符号，段落21及表格4
  - 风险分析：美术资源与程序逻辑对不上，且玩家看到“0”图案会误认为0倍，引发客诉。
  - 修改建议：将表格4的“乘数符号”列的“0”改为“空白”或“空”，并在文档中明确：图案为空白，乘数值为1。

  - 阻塞级别：阻塞测试用例设计

  - 证据来源：疯狂777需求文档修改后.docx / 游戏主模块展示界面，段落30
  - 风险分析：前后端金额展示可能因精度处理不一致出现微小差异，虽不阻断主流程但影响体验。
  - 修改建议：统一术语为“向下取整”，并明确服务端结算金额的数据精度（如：精确到分或整数）。
  - 关注角色：系统策划
  - 置信度：中
  - 阻塞级别：阻塞测试用例设计

### 【逻辑一致性与数值平衡】
- **[严重程度：高] 风控强制0倍逻辑与RESPIN触发条件存在致命冲突**
  - 现状描述：1、风控要求超过100倍时强制0倍，且123列至少一列为空；2、而RESPIN触发条件是123列均不为空。若RESPIN累加后超100倍触发风控，强行改空会导致逻辑崩溃，破坏RESPIN状态。
  - 证据来源：crazy777数值文档修改后.docx / 段落42、55-56、59
  - 风险分析：玩家看到123列中奖进入RESPIN，累加后突然某一列变空奖金清零，体验极差且逻辑上RESPIN触发条件被破坏。
  - 修改建议：1、明确风控介入时机：建议在基础盘面生成阶段控制，若基础盘面预期倍率>100则直接生成0倍盘面；2、或允许RESPIN结果突破100倍限制，不受此风控约束。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：中] RESPIN累加术语存在歧义，易导致实现误解**
  - 现状描述：需求文档举例使用加法(1+2+1+5)，数值文档也明确为“累加”且初始乘数为1，但通篇使用“乘数符号值”“累加乘数值”等术语，未直接说明是加法而非乘法，开发可能误解为乘法累乘。
  - 证据来源：疯狂777需求文档修改后.docx / 段落19；crazy777数值文档修改后.docx / 段落23、43-45
  - 风险分析：若开发误读为乘法，会造成赔付指数级爆炸，严重影响RTP，但结合上下文和举例可纠正，风险中等。
  - 修改建议：统一公式与术语，明确为“累加倍数”，公式写为：最终乘数 = 初始乘数(1) + Σ(每次重转倍数值)，并确保两份文档一致。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞测试用例设计
- **[严重程度：中] RESPIN次数与每次乘数值的抽取逻辑缺失**
  - 现状描述：配置了次数权重和单次乘数值权重，但未说明每次重转的乘数值是独立随机抽取还是按固定序列，也未说明总次数如何确定。
  - 证据来源：crazy777数值文档修改后.docx / 表格6、表格7，段落47-48、61
  - 风险分析：影响RTP计算与测试验收，若为独立抽取可能出现极端情况（如连续多次10倍）。
  - 修改建议：1、明确总次数是从表格6中按权重随机抽取一次，每次重转的乘数值从表格7中独立随机抽取，且最后一次重转强制为空；2、或给出其他确定规则。
  - 关注角色：数值策划
  - 置信度：中
  - 阻塞级别：阻塞测试用例设计
- **[严重程度：低] 推展机制术语与表现描述待澄清**
  - 现状描述：数值文档称“推展结算”，但举例及处理机制明确为“先得到最终结果，再进行一次表演”，实际是表现激励而非结果干预。术语可能引起误解，且“倍数”定义未明确指最终结算倍率。
  - 证据来源：crazy777数值文档修改后.docx / 五、基础游戏・推展机制，段落38-40
  - 风险分析：若未澄清，开发可能误以为需要修改结算结果，增加不必要的工作量或引入错误。
  - 修改建议：将“推展结算”改称“推展表现”，并明确此机制仅影响客户端动画，不影响服务端结算结果。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：不阻塞

### 【可测试性与验收标准】
- **[严重程度：低] 快捷旋转下RESPIN表现描述需进一步明确**
  - 现状描述：需求文档已说明自动旋转在RESPIN结算完成后停止，快捷旋转下RESPIN“是快速播放累加动画”，但文前“直接显示单次倍数叠加结果”与“快速播放累加动画”可能让实现者拿不准。
  - 证据来源：疯狂777需求文档修改后.docx / 游戏投注操作区域，段落35-36
  - 风险分析：开发可能误解为直接显示最终数值而跳过动画，但与需求“快速播放累加动画”矛盾，低风险。
  - 修改建议：明确快捷旋转下RESPIN表现为：不播放旋转动画，但快速播放累加动画（如数字快速滚动），最终显示累加后的总乘数。
  - 关注角色：系统策划
  - 置信度：中
  - 阻塞级别：不阻塞
