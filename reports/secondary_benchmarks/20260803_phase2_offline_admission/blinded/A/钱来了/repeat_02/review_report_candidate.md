# 需求文档分析报告

## 一、总体评价
文档主流程可理解，但仍存在中奖金额计算口径分裂且免费符号乘数缺失、乘数符号ID=0的表演权重替换逻辑表述不清、底层数据生成规则与RESPIN表演逻辑需澄清等高风险问题，建议补充对齐后再推进开发与测试。

- **文档质量评分：** C
- **评分原因：** 主流程可理解，但核心机制的底层逻辑与表演逻辑存在矛盾，风控与封顶规则口径冲突，且存在数值配置重复与关键规则缺失，需补充澄清后方可完整开工。

## 优先处理事项
- **[高] 中奖金额计算口径分裂且免费符号乘数缺失**
  - 责任建议：系统策划
  - 处理原因：1、程序在实现结算公式时可能因术语歧义导致乘区错误，引发严重的资金结算事故；2、免费符号结算无公式支撑，可能导致发奖错误。
- **[高] 乘数符号ID=0的表演权重替换逻辑表述不清**
  - 责任建议：数值策划
  - 处理原因：程序无法将此自然语言转化为代码逻辑，阻塞开发。
- **[高] 底层数据生成规则与RESPIN表演逻辑需澄清**
  - 责任建议：数值策划
  - 处理原因：1、底层逻辑与表演逻辑无法闭环，程序无法实现RESPIN的触发判定；2、程序无法确定最终配置，测试无法验收触发概率；3、测试无法验收免费游戏内的特色机制触发体验。

### 【逻辑一致性与数值平衡】
- **[严重程度：高] 中奖金额计算口径分裂且免费符号乘数缺失**
  - 现状描述：1. 需求文档将左右轴符号定义为“0.1倍、0.5倍...投注金额”，而数值文档定义为“金币赔率倍数”，且公式表述为“中奖金额 = 乘数符号 × 符号值（即基础投注 × 符号赔率）”，存在术语不一致与公式歧义。
2. 免费旋转符号触发时需支付基础奖金，但数值文档的结算公式未定义免费符号对应的乘数值，导致公式无法直接计算免费符号的奖金。
  - 证据来源：需求文档 / 3.3.1 符号分类总览、3.3.2 中间轴符号；数值文档 / 四、基础游戏・投注与中奖计算
  - 风险分析：1、程序在实现结算公式时可能因术语歧义导致乘区错误，引发严重的资金结算事故；2、免费符号结算无公式支撑，可能导致发奖错误。
  - 修改建议：1. 统一术语，将“金币赔率倍数”明确为“投注额乘数”，并给出无歧义的最终结算公式示例（如：中奖金额 = 基础投注 × 左/右轴乘数 × 中间轴乘数）。
2. 补充免费符号的结算规则，明确其乘数视为1倍，或单独定义免费符号的奖金计算公式。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：高] 乘数符号ID=0的表演权重替换逻辑表述不清**
  - 现状描述：数值文档描述“当表演权重随机到了2个免费类别时，随机将其中一个替换为100倍”，但乘数符号仅第2列有1个，未明确“2个免费类别”的指代对象及替换逻辑。
  - 证据来源：数值文档 / 三、基础游戏・乘数符号、表格3
  - 风险分析：程序无法将此自然语言转化为代码逻辑，阻塞开发。
  - 修改建议：重写该逻辑，明确是指“在表演权重池中连续抽取2次”还是“特定组合下的替换规则”，并给出具体示例。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：高] 底层数据生成规则与RESPIN表演逻辑需澄清**

3. 需求文档说明免费游戏内可触发重转/推展，但数值文档未提供免费游戏模式下的推展/RESPIN概率配置，仅说明“配置结构基本相同”。
  - 证据来源：数值文档 / 二、基础游戏・金币符号、五、基础游戏・核心机制；数值文档 / 表格5、表格6；需求文档 / 3.4.3 免费旋转模式；数值文档 / 八、免费游戏
  - 风险分析：1、底层逻辑与表演逻辑无法闭环，程序无法实现RESPIN的触发判定；2、程序无法确定最终配置，测试无法验收触发概率；3、测试无法验收免费游戏内的特色机制触发体验。
  - 修改建议：1. 澄清RESPIN是纯表演机制还是底层结果机制。若是表演机制，需明确底层数据如何映射到表演阶段的“1,3列不同且有值”的中间态。

3. 数值文档需补充免费游戏模式下的推展/RESPIN发生几率配置表。

  - 阻塞级别：阻塞开发
