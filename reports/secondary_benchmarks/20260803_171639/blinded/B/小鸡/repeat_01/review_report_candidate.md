2. 货币单位不统一：UI显示“3$”、“5$”，需求文档无单位，数值文档为纯数字，未说明筹码的货币单位与业务线自定义规则。
3. 动态筹码适配缺失：需求提及“筹码额度可各个业务自定义”，但未提供配置表结构、上下限、步长规则及UI自适应规则。
  - 证据来源：小鸡.docx / 2.2 详细规则，表格1；小鸡数值文档.docx / 2. 下注规则，表格1；图片1-7解析
  - 风险分析：1、需求、数值、UI三端筹码配置不一致，导致前后端无法对齐，阻塞下注系统开发与数值配置；2、前端UI无法适配动态筹码，可能导致不同业务线接入时界面错乱。
  - 修改建议：1. 统一三端筹码配置，建议以UI和实际需求为准（3、5、10、20），修正数值文档中的下注规则表格。
2. 明确筹码的货币单位，并补充动态筹码的配置表字段蓝图（最小值、最大值、步长、默认档位）及UI自适应规则。
  - 关注角色：策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：高] 概率算法、角色包装与UI展示多重冲突**
  - 现状描述：1. 概率算法冲突：需求文档表格2给出简单难度固定概率（20%、35%等），而数值文档采用Crash算法（MAX_MUL，首次必撞3%，非首次1%），两者底层逻辑互斥。
2. 角色与世界观包装冲突：需求文档段落55称“先用小鸡”，段落56定义“核心形象：卡通骆驼”，但所有UI截图（图片1-8）及游戏标题均为“CHICKEN ROAD”和小鸡形象，美术方向与文案割裂。
3. UI概率展示歧义：UI界面存在“被击中的概率”标签，但未说明在Crash算法下该概率是固定值、动态期望值还是基于当前格数的条件概率，测试无法验收。
  - 证据来源：小鸡.docx / 3.1 下注系统，表格2；小鸡数值文档.docx / 4. 撞击概率计算，段落11-17；小鸡.docx / 4、题材包装，段落55-56；图片1-8解析
  - 风险分析：1、需求文档描述的固定概率与数值文档的Crash动态概率算法完全冲突，阻塞核心碰撞逻辑实现；2、美术资源制作方向错误，可能导致返工；3、UI展示概率与实际结算概率不符，引发玩家客诉。
  - 修改建议：1. 废弃需求文档中的固定概率表格，统一采用数值文档的Crash算法，并补全4个难度的MAX_MUL配置。
2. 明确最终核心角色（建议以UI为准保留小鸡，重写世界观与场景包装）。
3. 明确UI“被击中概率”的计算公式（如：当前格撞车概率 = 1 - (下一格爆炸倍数期望 / 当前格爆炸倍数期望)），确保UI展示值与服务端底层概率严格一致。
  - 关注角色：策划/美术
  - 置信度：高
  - 阻塞级别：阻塞开发

### 【逻辑一致性与数值平衡】
- **[严重程度：高] 倍率计算公式与数值表口径严重冲突**
  - 现状描述：1、1. 公式口径冲突：需求文档段落44公式为“总奖金 = 下注金额 × Π(已通过马路倍率)”（单格连乘），但数值文档表格2提供的30个关卡数值明显为“累计倍率”（如难度1第30关23.9符合24倍盘）。；2、2. 数值表数据崩坏：数值文档表格2中，难度3定义为“103倍盘”，但第30关数值为624.86；3、难度4定义为“176倍盘”，第30关数值高达66278475.57。数据与命名存在巨大数量级差异，疑似公式推导或填表错误。
  - 证据来源：小鸡.docx / 3.3 奖金计算系统，段落44；小鸡数值文档.docx / 3. 难度选择，表格2
  - 风险分析：1、若按单格连乘，数值将完全崩坏；2、若按累计倍率，需求公式错误。数值表难度3、4的数据崩坏直接导致最高赔付失控或玩家体验崩坏。
  - 修改建议：1. 明确数值表口径为“累计倍率”，将需求文档公式修正为“总奖金 = 下注金额 × 当前所在马路的累计倍率”。
2. 数值策划需重新校验难度3和难度4的赔率推导公式，确保第30关的最终累计倍率与“103倍盘”、“176倍盘”的命名定义严格对齐，修复填表错误。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：高] 通关“超级大奖”与第30格结算的边界歧义**
  - 现状描述：1. 结算叠加歧义：需求文档提及“成功通过所有预设马路，触发超级大奖”，数值文档明确为30个格子。未说明第30格是仅按第30格累计倍率结算，还是额外叠加固定/动态的超级大奖金额。
2. Crash映射歧义：数值文档采用Crash连续算法（随机爆炸倍数），但玩法是离散的30个格子。未说明“爆炸倍数”如何映射到“第几格撞车”（如：随机爆炸倍率为2.5，玩家在第N格累计倍率>2.5时触发撞车）。
  - 证据来源：小鸡.docx / 2.1 完整游戏流程，段落31；小鸡数值文档.docx / 3. 难度选择，段落9；小鸡数值文档.docx / 4. 撞击概率计算，段落11-13
  - 风险分析：1、结算逻辑存在分支歧义，可能导致巨额重复赔付或逻辑报错；2、核心碰撞判定逻辑无法实现，测试无法验收离散格子与连续倍率的映射关系。
  - 修改建议：1. 明确第30格的结算公式，建议定义为“通过第30格后，总奖金 = 下注金额 × 第30格累计倍率 + 超级大奖固定金额”，并给出超级大奖的具体数值。
2. 补充爆炸倍数到离散格子的映射规则示例，明确当随机值介于两格累计倍率之间时的判定规则。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
