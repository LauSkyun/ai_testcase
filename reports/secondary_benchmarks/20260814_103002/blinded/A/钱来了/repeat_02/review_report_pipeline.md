# 需求文档分析报告

## 一、总体评价
文档整体描述了3轴1行老虎机的核心玩法与数值框架，主流程基本可理解。但核心机制（RESPIN、推展）的底层数据与表演逻辑存在矛盾，风控基数与封顶规则口径不清，且存在多处数值配置冲突与逻辑缺失，需补充澄清后方可进入开发。

- **文档质量评分：** C
- **评分原因：** 主流程可理解，但核心机制的底层逻辑与表演逻辑存在矛盾，风控与封顶规则口径冲突，且存在数值配置重复与关键规则缺失，需补充澄清后方可完整开工。

## 优先处理事项
- **[高] 底层数据生成规则与RESPIN触发条件矛盾**
  - 责任建议：数值策划
  - 处理原因：底层逻辑与表演逻辑无法闭环，程序无法实现RESPIN的触发判定。；程序无法确定最终配置，测试无法验收触发概率。；测试无法验收免费游戏内的特色机制触发体验。
- **[高] 中奖金额计算公式与符号定义口径分裂**
  - 责任建议：系统策划
  - 处理原因：程序在实现结算公式时可能因术语歧义导致乘区错误，引发严重的资金结算事故。
- **[高] 乘数符号ID=0的表演权重替换逻辑表述不清**
  - 责任建议：数值策划
  - 处理原因：程序无法将此自然语言转化为代码逻辑，阻塞开发。

## 二、逐维度问题清单
### 【清晰度与完整性】
- **[严重程度：中] 推展机制的“上下”方向与1x3盘面结构冲突**
  - 现状描述：需求文档定义盘面为“1行3列”，但推展机制描述为“中间轴将有机会向上或向下推展一次”。数值文档举例称“上方或下方的一个乘数为X3”，未说明1行盘面如何表现上下推展。
  - 证据来源：需求文档 / 3.2.1 卷轴结构、3.4.2 推展模式；数值文档 / 五、基础游戏・核心机制
  - 风险分析：视觉表现与底层逻辑脱节，程序无法确定推展动画的源数据位置及中奖线判定规则。
  - 修改建议：明确推展的视觉表现（如：是否指代卷轴上下相邻的隐藏符号行），并补充推展后符号落定中奖线的判定规则。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞开发

### 【逻辑一致性与数值平衡】
- **[严重程度：高] 中奖金额计算公式与符号定义口径分裂**
  - 现状描述：需求文档将左右轴符号定义为“0.1倍、0.5倍...投注金额”，而数值文档定义为“金币赔率倍数”，且公式表述为“中奖金额 = 乘数符号 × 符号值（即基础投注 × 符号赔率）”，存在术语不一致与公式歧义。
  - 证据来源：需求文档 / 3.3.1 符号分类总览、3.3.2 中间轴符号；数值文档 / 四、基础游戏・投注与中奖计算
  - 风险分析：程序在实现结算公式时可能因术语歧义导致乘区错误，引发严重的资金结算事故。
  - 修改建议：统一术语，将“金币赔率倍数”明确为“投注额乘数”，并给出无歧义的最终结算公式示例（如：中奖金额 = 基础投注 × 左/右轴乘数 × 中间轴乘数）。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：高] 乘数符号ID=0的表演权重替换逻辑表述不清**
  - 现状描述：数值文档描述“当表演权重随机到了2个免费类别时，随机将其中一个替换为100倍”，但乘数符号仅第2列有1个，未明确“2个免费类别”的指代对象及替换逻辑。
  - 证据来源：数值文档 / 三、基础游戏・乘数符号、表格3
  - 风险分析：程序无法将此自然语言转化为代码逻辑，阻塞开发。
  - 修改建议：重写该逻辑，明确是指“在表演权重池中连续抽取2次”还是“特定组合下的替换规则”，并给出具体示例。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：高] 底层数据生成规则与RESPIN触发条件矛盾**
  - 现状描述：1、数值文档称“不会生成1,3均不为空的局面”，但又规定“当1,3列金币符号不同且有值时...必定发生RESPIN”。若底层不生成1,3均不为空，则RESPIN的触发条件在底层数据中无法成立。；2、数值文档中出现了两个“RESPIN发生几率”表格，表格5配置为0.1，表格6配置为0.05，存在直接冲突。；3、需求文档说明免费游戏内可触发重转/推展，但数值文档未提供免费游戏模式下的推展/RESPIN概率配置，仅说明“配置结构基本相同”。
  - 证据来源：数值文档 / 二、基础游戏・金币符号、五、基础游戏・核心机制；数值文档 / 表格5、表格6；需求文档 / 3.4.3 免费旋转模式；数值文档 / 八、免费游戏
  - 风险分析：1、底层逻辑与表演逻辑无法闭环，程序无法实现RESPIN的触发判定。；2、程序无法确定最终配置，测试无法验收触发概率。；3、测试无法验收免费游戏内的特色机制触发体验。
  - 修改建议：1、澄清RESPIN是纯表演机制还是底层结果机制。若是表演机制，需明确底层数据如何映射到表演阶段的“1,3列不同且有值”的中间态。；2、删除冗余或错误的表格，统一RESPIN触发概率配置，并明确该概率是基于最终结果还是表演权重的计算基数。；3、数值文档需补充免费游戏模式下的推展/RESPIN发生几率配置表。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：高] 风控倍数基数与免费游戏封顶规则冲突**
  - 现状描述：数值文档规定“超过100倍 → 直接强制0倍”，而需求文档规定“免费模式中总赢奖达到投注额的2000倍时，自动结束”。两份文档均未明确“倍数”的基数是“单局投注额”还是“免费游戏累计投注额”。
  - 证据来源：需求文档 / 3.4.3 免费旋转模式；数值文档 / 六、基础游戏・体验控制 & 风控
  - 风险分析：1、若风控基数为单局，则免费游戏可正常累计至2000倍；2、若为累计，则免费游戏永远无法触发2000倍封顶。口径不清将导致风控逻辑与封顶逻辑互斥。
  - 修改建议：明确风控“100倍”的基数为“单局赔付/单局投注”，并补充说明免费游戏2000倍封顶的统计口径（如：单次免费游戏周期内的累计总赢奖）。
  - 关注角色：系统策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：中] 免费游戏续杯概率配置缺失**
  - 现状描述：1、需求文档明确免费游戏内可再次触发免费旋转（续杯），但数值文档仅提及“概率独立配置”，未提供具体的概率表或配置结构。；2、需求文档仅提及OMS后台控制购买免费游戏的价格系数，未说明购买价格的具体公式、购买后的初始免费次数、以及购买后是否还能触发自然免费等核心规则。
  - 证据来源：需求文档 / 3.4.3 免费旋转模式；数值文档 / 八、免费游戏；需求文档 / 3.5.3 购买免费游戏
  - 风险分析：1、测试无法验收续杯体验，程序无法实现免费游戏内的独立概率控制。；2、阻塞购买功能的开发与测试用例设计。
  - 修改建议：1、数值文档需补充免费游戏内的乘数符号（含免费5/10/20）出现权重表，明确续杯概率。；2、补充购买价格公式（如：基础投注 × 系数 × 固定次数）、购买后进入的免费游戏初始次数，以及购买状态与自然触发的互斥/叠加规则。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
