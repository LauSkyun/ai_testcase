# 需求文档分析报告

## 一、总体评价
文档主流程可理解，但仍存在倍率计算公式与数值表口径严重冲突、下注筹码数值配置冲突、通关‘超级大奖’与第30格结算的边界歧义等高风险问题，建议补充对齐后再推进开发与测试。

- **文档质量评分：** C
- **评分原因：** 主流程可理解，但核心结算公式、Crash算法映射、下注筹码及难度概率存在多处高风险冲突与缺失，需补充修正后才能开工。

## 优先处理事项
- **[高] 倍率计算公式与数值表口径严重冲突**
  - 责任建议：待定
  - 处理原因：需求公式要求‘单格倍率连乘’，但数值表提供的明显是‘累计倍率’（难度1第30关23.9符合24倍盘命名）。若按单格连乘，数值将完全崩坏；若按累计倍率，需求公式错误。；数值表存在明显配置错误或公式推导错误，直接导致最高赔付失控或玩家体验崩坏。
- **[高] 下注筹码数值配置冲突**
  - 责任建议：待定
  - 处理原因：需求、数值、UI三端筹码配置不一致，导致前后端无法对齐，阻塞下注系统开发与数值配置。；前端UI无法适配动态筹码，可能导致不同业务线接入时界面错乱。
- **[高] 通关‘超级大奖’与第30格结算的边界歧义**
  - 责任建议：数值策划
  - 处理原因：结算逻辑存在分支歧义，可能导致巨额重复赔付或逻辑报错。；核心碰撞判定逻辑无法实现。若爆炸倍数指累计倍率，需明确当随机值介于两格累计倍率之间时的判定规则。

### 【安全性与反作弊】
- **[严重程度：高] 单局绝对赔付金额封顶（MAX_PAYOUT）缺失**
  - 现状描述：小鸡数值文档.docx 段落13-14及表格3定义了相对倍率上限 MAX_MUL（如难度4为176倍），但未定义单局绝对赔付金额封顶（如单局最多赔付10000元）。
  - 证据来源：小鸡数值文档.docx / 4. 撞击概率计算，段落13-14、表格3。
  - 风险分析：若业务线自定义下注金额上限极高，结合176倍MAX_MUL，单局赔付可能超出平台或单业务线的风险承受阈值，引发重大资损。
  - 修改建议：补充单局绝对赔付金额封顶配置（MAX_PAYOUT）。明确当计算奖金超过该封顶值时，是截断至封顶值、还是强制触发撞车失败。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
  - 问题来源：副评审补充 (variant_A)
- **[严重程度：高] 本金扣除时机与失败‘清零’口径歧义**

  - 证据来源：小鸡.docx / 2.1 完整游戏流程，段落20-22、26；小鸡数值文档.docx / 1. 游戏简介，段落3。

## 三、核心测试点建议
### 功能验证
- 验证下注、选难度、开始、前进、提现、失败、通关的完整主流程。

- 弱网环境下快速重复点击‘开始’和‘提现’按钮，验证幂等性。
