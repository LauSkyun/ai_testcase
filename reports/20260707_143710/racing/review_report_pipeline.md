# 需求文档分析报告

## 一、总体评价
文档描述了完整的赛车竞猜玩法循环，包含下注、开奖、奖池干预等核心机制。但核心赔率公式在需求与数值文档中存在严重冲突，且最大赔付兜底、异常状态恢复、干预逻辑优先级等关键边界缺失，需补充后方可进入开发。

- **文档质量评分：** C
- **评分原因：** 主流程可理解，但核心赔率计算存在两套冲突公式，且最大赔付兜底、异常状态恢复及干预逻辑优先级等关键边界缺失，存在结算事故风险。

## 优先处理事项
- **[高] 核心赔率公式在需求与数值文档中存在严重冲突**
  - 责任建议：数值策划
  - 处理原因：两套公式逻辑完全不同，开发无法确定最终展示和结算使用哪套逻辑，直接阻塞核心结算链路。；如果假数据参与计算，会稀释真实奖池或扭曲真实赔率；如果不参与，前端展示的赔率与真实结算赔率将产生割裂。
- **[高] 最大赔付上限与奖池负数兜底机制缺失**
  - 责任建议：数值策划
  - 处理原因：极端情况下（如高赔率选项被大R重注且开奖），可能导致单局赔付远超奖池，造成平台严重资损。

  - 责任建议：程序
  - 处理原因：如果客户端参与赔率计算或干预逻辑，极易被外挂利用进行套利；缺乏防篡改说明可能导致资金安全问题。

### 【清晰度与完整性】
- **[严重程度：高] 核心赔率公式在需求与数值文档中存在严重冲突**
  - 现状描述：1、需求文档定义实时赔率为“合计下注/本选项下注*[001]%”（段落28），而数值文档定义为“Odds_X = (T * (1 - r) / W_X) * γ”（图片1），且数值文档提到“分实际赔率和假赔率”（段落5）。；2、需求文档（musee游戏Racing.docx / 3.3下注部分 段落28）定义实时赔率为基于资金池比例的公式（合计下注/本选项下注*[001]%），而数值文档（Racing数值文档.docx / 图片1）定义为基于时间、权重和gamma系数的公式（Odds_X = (T * (1 - r) / W_X) * γ）。两者逻辑完全不同，且数值文档提到“分实际赔率和假赔率”，未说明与需求文档公式的映射关系，导致结算链路无法实现。；3、文档提到“假人数是真实人数乘系数”（段落22）、“假金额”（段落23），但未说明这些假数据是否注入真实奖池，是否参与“实时赔率”的分子分母计算。
  - 证据来源：musee游戏Racing.docx / 3.3下注部分 段落28；Racing数值文档.docx / 图片1、段落5；['musee游戏Racing.docx / 3.3下注部分 段落28', 'Racing数值文档.docx / 图片1、段落5']；musee游戏Racing.docx / 3.3下注部分 段落22-23；3.4开奖逻辑 段落37

  - 修改建议：1、统一赔率公式。明确“假赔率”用于前端展示，“实际赔率”用于服务端结算的具体映射关系，并废弃或整合冲突的公式。；2、数值策划与系统策划需对齐赔率模型，统一最终结算公式。明确“假赔率”用于前端展示，“实际赔率”用于服务端结算的具体映射关系，并废弃或整合冲突的公式。；3、明确假人数/假金额仅用于前端展示（氛围），不参与服务端奖池注入与真实赔率计算，并在文档中声明数据源隔离规则。
  - 关注角色：数值策划
  - 置信度：高
  - 阻塞级别：阻塞开发
- **[严重程度：中] 下注扣款与结算发奖的时机及幂等性未定义**

## 三、核心测试点建议
### 功能验证
- 验证下注、开奖、结算的主流程是否顺畅，扣款与发奖金额是否准确。
- 验证实时赔率的动态变化是否符合公式，展示赔率与结算赔率是否一致。
- 验证奖池状态（待补充、正常、充裕）下的干预逻辑是否按预期触发。
- 验证统计板块的胜率、赔率排行及今日/周榜的数据准确性。
### 异常操作
- 弱网/断线环境下，下注阶段重连后下注记录与余额是否一致。
- 开奖阶段或结算弹窗时断线重连，结果展示与资产结算是否正确。
- 快速重复点击下注按钮，验证是否触发幂等校验，防止重复扣款。
- 余额不足时点击MAX或下注，验证提示与拦截逻辑。
### 兼容性
- 全屏与半屏切换时，UI布局、下注面板、结果弹窗的层级与适配。
- 半屏模式下，直播间音频与游戏音效的混音/互斥表现。
- 不同分辨率设备下，统计板块、排行榜的滑动与吸底效果。
### 安全专项
- 抓包修改下注金额、下注选项，验证服务端是否校验并拒绝。
- 修改本地配置（如地形系数、基础速度），验证是否影响服务端开奖结果。
- 验证假人数、假金额数据是否严格隔离，不参与真实奖池与赔率计算。
### 回归影响
- 配置热更（如修改地形系数、赔率参数）后，当前局与下一局的表现。
- 跨天/跨周（GMT+5.5）时，今日/周榜数据的刷新与重置。
### 性能与稳定性
- 下注阶段倒计时30S内，高频刷新下注人数/金额的性能消耗。
- 开奖阶段3段地形动画播放时的帧率与内存占用。
- 长时间挂机或连续多局游戏后的内存泄漏检查。
### 用户体验
- 新手引导5个步骤的流畅度，固定赔率与真实玩法的过渡体验。
- 未中奖用户的失败反馈与复盘信息展示。
- 结果弹窗中TOP3用户昵称过长时的截断与展示效果。
